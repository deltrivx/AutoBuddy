> 修复「你可以做什么」收不到回复——企微 5 秒硬限制下 LLM 回复被丢弃；改为能力问句即时答 + LLM 延后推送。

## 用户反馈

> 「我刚刚发送了一个：你可以做什么，到现在都没回我……我说了你可以参考
> MoviePilot 的智能助手，只是那个服务 MP 这个服务 AutoBuddy，不是让你自己
> 从 0 开始写个半成品」

## 实测根因（架构缺陷，不是 prompt 问题）

实测链路耗时：

```
Q: 你可以做什么
   (9.0s) 我可以帮你查询 AutoBuddy 网关的各类实时状态，主要有这些：...
   判定: ❌ 超时！企微会丢弃回复
```

企微「接收消息服务器」要求 **5 秒内**返回响应体，超时即丢弃。
服务侧其实算出来了，但企微把回复丢了 —— 用户侧表现为「没回」。

**根本原因**：我之前只研究了 MoviePilot 的 LLM **provider 配置**，
没研究它怎么解决**消息时限**这个更基础的问题。

## 参考 MoviePilot 的解法

研究 `app/application/messaging/ingress.py` 后确认其分层：
**渠道只负责接收与即时回执，重活交给后台，结果走主动推送通道。**

## 修复（三道防线）

### 1. 能力/菜单类问句 → 本地即时生成

「你可以做什么」「有什么功能」「怎么用」这类是最高频的「上手第一问」，
却**完全不需要查实时数据**。用 LLM 答既慢又浪费，还容易踩 5 秒红线。

现在本地生成，实测 **0.001 秒**（原 9 秒）。

### 2. 能映射到只读命令的疑问句 → 本地即时查

确定性路径，最稳最快，不依赖模型可用性。

### 3. 真需要 LLM 的问题 → 先回执 + 后台推送

企微回调传 `allow_defer=True`：

```
用户: 现在积分多少
助手: 🤔 正在查询，请稍候～
       结果出来后我会主动推送给你。      ← 5 秒内返回 ✅
（后台 9 秒后）
助手: [主动推送] 剩余积分：40,980.82 ...  ← 走通知通道送达
```

两个设计点：

- **全局单工**（`_DEFER_BUSY`）：同一时刻只跑一次 LLM。既防并发打爆模型，
  也防用户连发多条导致推送刷屏；
- **绕过通知总开关**：这是「用户问的答复」，不是例行通知，
  不该被通知总开关拦掉（但仍是私聊推送，不会进群）。
