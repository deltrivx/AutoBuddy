# AutoBuddy v0.9.20

> access log 通用相邻去重：相同的日志只出现一条。

## 问题：日志刷屏

你反馈「相同时间日志完全一模一样出现也没有意义，出现一条即可 ——
即便是调用 API 的日志」。实测属实，且比想象的严重：

抓取容器最近 2322 行日志做归一化统计（抹掉每次连接都不同的客户端端口号）：

```
总行数                 2322
归一化后不同内容        106
uvicorn access log 占比 98%
```

重复次数 Top：

```
1533x  GET /api/switch/progress
 119x  GET /api/travel/status
  88x  GET /api/wb-daily/credit-summary
  45x  GET /api/status
  43x  GET /health
```

**`/api/switch/progress` 一条就占全部日志的 66%**，
真实请求（`POST /v1/chat/completions`）反而被淹掉。

## 根因：黑名单追不上

v0.9.0 已有 `_AccessNoiseFilter`，但它是**路径黑名单**：

```python
NOISY_PATHS = ("/health", "/api/status", "/api/gateway-info", ...)
```

而刷屏最凶的三个接口 —— `/api/switch/progress`、`/api/travel/status`、
`/api/wb-daily/credit-summary` —— **全都不在名单里**。

黑名单的固有问题是：**每新增一个轮询接口就要手工补一次，永远追不上**。

## 方案：通用相邻去重

新增 `_AccessDedupFilter`，与黑名单**互补而非互斥**：

| 机制 | 职责 |
| :--- | :--- |
| `_AccessNoiseFilter`（黑名单） | 已知且确定无信息量的接口，连第一条都不打 |
| `_AccessDedupFilter`（去重） | **其余所有接口**，保留第一条，后续只累计 |

好处：**新增轮询接口无需改代码，自动生效**。

### 三个关键设计点

**1. 端口号归一化（最容易漏）**

```
192.168.31.10:57564  →  192.168.31.10
```

同一接口每次连接的**临时端口不同**，不归一化则两条日志永远判不相等，
去重彻底失效。

**2. 按内容各自独立记录**

access log 是**多路交错**的（A、B 两个接口交替轮询）：

```
A, B, A, B, A, B ...
```

单纯「与上一条比较」会被交错打断而失效。所以按规范化后的内容
**各自独立**记录上一条，互不干扰。

**3. 重复时补交代**

内容变化时会先打一行：

```
INFO:     (上一条重复 N 次) ...
```

避免观测断档——被吞掉的次数是明确交代的，不是悄悄消失。

**4. 只作用于成功响应**

4xx/5xx 一律保留线索（沿用既有行为），不把故障线索一起静音。

## 回归测试

新增 `_test_log_dedup.py`，校验：

- 去重类存在、已挂载到 `uvicorn.access`
- 端口归一化实现到位
- `re` / `threading` 已导入（否则运行时 `NameError`）
- 三个行为场景：
  - 端口不同的相同请求 → 只留一条
  - 交错轮询 A,B,A,B → 各自独立去重
  - 不同接口 → 不被误杀

顺带补齐了 `gateway/web_proxy.py` 缺失的 `import re` 与
`import threading`（此前未导入，加了去重实现会直接 `NameError`）。
