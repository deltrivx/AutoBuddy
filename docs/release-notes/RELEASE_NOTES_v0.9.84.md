## 二、任务积分规则表（新增）

### 背景

用户问「当前任务执行进度到哪了，执行完后预计多少积分收益？」时，助手答不出来
—— 数据源里 `total_credits` 恒为 null，没有规则可依。

### 规则（全部实测，无编造）

**签到 —— 精确可算**

22 账号 × 5 个样本点，规律完全吻合：

```
连签 4 天  → 累计  400
连签 8 天  → 累计  800
连签10 天  → 累计 1000
连签11 天  → 累计 1100
连签16 天  → 累计 1600
```

规律：**100 积分/天 × 连签天数**（纯累加，非递增）。

**领奖 —— 精确可算**

```
Expert_lighthouse  →  +100 积分 +5 能量
RichMeow_Chat      →  +100 积分 +5 能量
```

依据：全流程实测 43 次领奖记录。

**服务端下发 —— 不可预算**

旅行礼物（`reward_credit`）、连签兑换（`credit_granted`）、新手礼包（`credit`）
的值由服务端决定，只能读实际返回值。

**历史量级 —— 统计口径**

近 21 天台账「任务」列实测区间：600 ~ 7,100 积分/天。

### 助手新增工具

- `get_credit_rules`：返回完整规则表
- `estimate_credits`：按连签天数 + 剩余任务估算，**明确区分「可精确算」与「估算区间」**

示例输出：

```
积分收益估算：
  【可精确算】
    · 签到（连签 16 天）：+1600
    · Expert_lighthouse：+100
    · 小计：1,700 积分
  【估算区间】600 ~ 7,100 积分/天
    · 浮动部分取决于服务端下发的奖励，按近 21 天实测区间估算
```
