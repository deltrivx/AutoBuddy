修搜索栏误注入数据总览页 —— 页面守卫误判「根路径无 hash」为账号页，官方路由里那是总览；CDP 实证修复。

## 一、问题

用户反馈：

> 积分统计页面也出现搜索栏，我说了只需要在账号统计页面出现即可

v1.0.22 已加过页面守卫（`wbIsAccountsPage()`），但**没修住**。CDP 复测发现搜索栏出现在了**数据总览页**上。

## 二、根因

守卫的判据写错了一半：

```js
if (hash === "#/accounts") return true;
// 官方根页（无 hash 后缀）就是账号管理页的背后页面。
if ((path === "/" || path === "") && (hash === "" || hash === "#/" || hash === "#")) return true;
```

第二条把「根路径 + 无 hash」当成账号管理页。但同一文件里的官方路由规则（`wbResolveView`）写得很清楚：

| 条件 | mode |
| :--- | :--- |
| `path === "/"` 且 `hash === ""` | **overview（数据总览）** |
| `hash === "#/accounts"` | **accounts（账号管理）** |

关键点：账号管理的背后页面正是官方 `/`，所以 SPA 切到数据总览时，**账号页仍挂在 DOM 里**（只是被总览浮层盖住），档位 tablist 也一并存在 —— 于是那条错误判定让搜索栏被插到了总览页上。

### CDP 实证（修复前）

| 页面 | `#wb-account-search-bar` | 输入框 visible |
| :--- | :--- | :--- |
| `http://192.168.31.2:18090/`（无 hash = 总览） | **count=1** | **false**（被浮层盖住） |
| `http://192.168.31.2:18090/#/accounts` | count=1 | true |

总览页上有一个看不见却存在着的搜索栏 —— 正是用户看到的现象。

## 三、修复

守卫改为**只认一条判据**：

```js
function wbIsAccountsPage() {
  var hash = "";
  try {
    hash = (typeof location !== "undefined" && location.hash) || "";
  } catch (e) {}
  return hash === "#/accounts";
}
```

根路径无 hash 一律不注入，数据总览 / 积分统计 / 词元统计天然全部排除。

### CDP 实证（修复后）

| 页面 | `#wb-account-search-bar` | 输入框 visible |
| :--- | :--- | :--- |
| 数据总览（无 hash） | **count=0** | — |
| 账号管理（`#/accounts`） | count=1 | **true** |

## 五、Mac-mini DSH 400：诊断结论（未改动代码）

本轮用户反馈「400 依然未消除，连接 mac 查看具体原因，别乱猜乱修」。臣按此旨意只做诊断、不改代码：

1. **在网关注入临时诊断日志**（只记请求头与 body 结构，不记内容与凭证），抓到 DSH 的真实请求形态：`OpenAI/JS 7.27.0` UA + 11 个 tools + `tool_choice="auto"` + `max_completion_tokens=8192` + `stream=True`，请求体 1.4~3.2 MB。
2. **按该精确形态做 A/B 剥离**（4 变体）：完整形态 / 去 tools / 只留 tools / 只留 maxct —— **全部 200，无一触发 11128**。
3. **再加码复现**：61 万字符、36.6 万 token、完整 DSH 形态，连发两次 —— **全部 200**。
4. **按客户端 IP 精确归因**：Mac-mini 近 40 分钟 **200×4、400×1**；近 12 分钟 **400×0**。唯一那次 400 发生在容器重启前，当时是**两个请求并发**、各跑 9 次换号重试共 18 次撞同一批账号。

**结论**：11128 与请求特征**完全无关**（头族 / tools / tool_choice / max_tokens / 体量全部排除），属上游间歇性账号级拦截，触发条件与请求并发密度相关。v1.0.22 的换号重试（实测跑到第 9 次）正在按设计兜底。

**诊断日志已按承诺移除**，计时复验新产生行数为 0。
