# AutoBuddy v2.3.2 发布说明

## 修复：智能路由页两处缺陷（PC 无法选智能路由 + 移动端错位）

v2.3.1 把智能路由链路打通了，但上线后暴露两个前端缺陷：PC 端打不开智能路由选择、移动端布局横向错位。v2.3.2 一并修复。

### 根因 1：视图拼接漏写加号，整段被静默丢弃

`wbCreateRoutingView()` 在拼接 HTML 字符串时，`'<section class="wb-rt-card wb-rt-prov-card">'`（多账号 / 多 KEY）那一行末尾漏写了 `+`。

JavaScript 字符串拼接里，漏 `+` 的连接效果不是「少一段」，而是「这一行之后的所有字符串字面量都变成无效语句」——于是多账号 / 路由策略 / 自动路由状态 / 路由组 / 路由规则这五大区块全部不渲染，页面只剩半截模板。

后果：路由页看起来「加载出来了」却选不了智能路由（因为模式选择器所在的整段根本没生成）。补回 `+` 后五大区块恢复正常，config 与 providers 两处「智能路由」模式选择器都能点击并写回（经 `/api/routing/config` PUT，返回 200）。

### 根因 2：分段控件不换行，撑破卡片

路由页的分发模式选择器 `.am-seg` 原本是 `display:inline-flex; flex:none`，既不换行也不限宽。10 个模式（智能 / 顺序 / 用尽为止 / 轮转 / 最少使用 / 到期前先用 / 免费优先 / 速度优先 / 按权重 / 手动）横向排开约 592px，直接撑破卡片、引发整页横向滚动。

移植 Magpie 的窄屏规则：`@media (max-width: 760px)` 下改为 `display:flex; width:100%; flex-wrap:wrap`，卡片加 `overflow:hidden; min-width:0`，标签行在窄屏纵向堆叠。修复后移动端无横向溢出（新开浏览器上下文实测 `docOverflow:0`、各卡片无溢出）。

### 升级说明

- 仅前端样式与视图拼接修复，无破坏性变更；v2.3.x 的路由表、账号池与配置数据全部兼容保留。
- 升级后直接可用，无需手动迁移。
