> 仅含账号级停用策略的运维数据清理与版本号推进，**代码零改动**。

## 一、本版性质

这是一个**运维清理版**，不包含任何功能新增或逻辑修改。镜像内容与 `v1.0.2` 等价，
升级不会改变网关的任何运行行为。之所以单独出一个版本号，是为了把「账号策略脏数据
已清理」这件事在发布记录里留痕，便于日后对照线上状态。

## 二、清理了什么

`account_policy.json`（账号级停用策略）里积累了 **7 条 `auto` 来源的停用记录**，
它们指向的账号 id 早已不在账号池内：

| 账号 id（前 8 位） | 来源 | 在池内 |
| :--- | :--- | :--- |
| `1a3478dc` | auto | 否 |
| `e983e932` | auto | 否 |
| `bcfa0951` | auto | 否 |
| `e642fc75` | auto | 否 |
| `617f9c0f` | auto | 否 |
| `8e83e261` | auto | 否 |
| `3db04d0e` | auto | 否 |

**影响面**：这些条目**不影响轮询**——白名单非空时，池外账号本就不参与选号。
它们只让 `/account-pool/status` 的 `accountDisabled` 计数虚高（清理前 8 条，
清理后 1 条），以及前端的「已停用」徽标显示不符实际。

**保留项**：`a75e21b0`（来源 `manual`）。人工停用属于明确的人为决定，
巡检不得替人放开，也不应被当作脏数据清掉。

**备份**：清理前文件已整份备份，见下节。

## 四、一处需更正的文档事实

会话粘性的两个参数**早已可配置**，不需要发版即可调整，本版也没有改动它们：

| 环境变量 | 位置 | 默认值 |
| :--- | :--- | :--- |
| `AB_STICKY_TTL` | `gateway/session_sticky.py` | `1800`（秒） |
| `AB_STICKY_QUOTA_FACTOR` | `gateway/main.py` | **`1.5`** |

此前有文档与口述把 `AB_STICKY_QUOTA_FACTOR` 的默认值记成 `2.0`，**以代码为准是 `1.5`**。
这里显式记录，避免再次记错。

注意：`_test_sched_decay_retryafter.py` 对上述默认值（以及
`AB_STICKY_QUOTA_MIN_GAP = 1.0`）有**硬编码断言**。若将来要调整默认值，
必须同步更新该测试，否则 CI 会直接变红。

调整粘性只需在容器环境里设变量并重建容器，**无需回滚镜像**：

```
AB_STICKY_TTL=600
AB_STICKY_QUOTA_FACTOR=1.3
```

## 五、升级方式

镜像标签 `v1.0.3` / `1.0.3` 与 `latest` 均已推送。数据目录结构无变化，
直接重建容器即可，无需迁移。

## 六、后续版本

四项代码改动（选号后回查、`inflight` TTL 回收、选号流水锁外去抖落盘、
上游异地登录归类）与 `export-accounts` 默认脱敏，均**不在本版内**，
已整理为 `v1.0.4` 的输入清单，将单独验证后发布。这些改动位于请求热路径，
不适合与本清理版混发。
