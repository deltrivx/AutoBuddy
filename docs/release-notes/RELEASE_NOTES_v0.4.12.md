## 一、修复：错误档配色从未生效

提示条按结论分档着色，但红色档一次也没命中过 —— 调用方生成的类名是
`wb-api-toast-error`，样式表里定义的却是 `.wb-api-toast-err`，两个名字对不上。

后果是凭据失效的提示静默落到默认档，和普通提示长得一样。这类「两边各写一个名字」
的错不会报错、只会降级，所以一直没人发现。

现在统一为 `-err`，并让样式表同时兼容 `-error` 写法 —— 调用方以后再写错其中一个，
也只是多一条冗余规则，不会又变成「看起来没生效」。测试里加了一条反向检查：
提示条引用的每个档位，样式表里必须有对应定义。

## 二、修复：提示配色与结论一一对应

「检测账号」的提示条此前只有两种配色：默认的深色，和出错时的红色。账号被上游内容
审查拦截时返回 403，同样落进红色档 —— 于是「凭据已失效」和「账号受限」在界面上
长得一模一样，而这两者的处理方式正好相反，一个要重新登录，一个重新登录没有用。

现在提示条按结论分三档：

| 结论 | 配色 |
| :--- | :--- |
| 凭据有效 | 绿色 |
| 账号受限 | 琥珀色 |
| 凭据已失效 | 红色 |

颜色即结论，不必先读完整句话再判断要不要处理。

## 三、修复：提示条在移动端不再溢出

提示条此前没有宽度上限，也不允许换行。在移动端，一条稍长的结论会被拉成超出屏幕的
横条，背景随之外溢、被裁切 —— 这正是「背景很奇怪」的来源：看到的不是配色有问题，
而是提示条本身已经不是一个完整的块。

现在限制最大宽度并允许换行，圆角由胶囊形改为常规提示条样式，长结论会正常折行。

## 四、修复：「凭据有效」不再附带读作故障的说明

正常账号此前提示：

> 凭据有效，但上游以未知模型拒绝

后半句的本意是交代判定依据 —— 探测刻意用一个不存在的模型名，上游如实回应「该模型
不存在」，恰恰说明它已经认下了这张凭据。措辞却让人以为上游在报错，于是账号明明是
正常的，提示读起来像出了故障。

现在改为直接说明探测方式，不再出现「拒绝」「失败」「异常」一类字眼。

## 不改变的行为

- 账号有效性的判定标准不变，本轮只改提示的呈现，不改任何结论。
- 提示的持续时间与出现位置照旧。
- 巡检默认仍为关闭状态，间隔与账号范围的配置方式照旧。
