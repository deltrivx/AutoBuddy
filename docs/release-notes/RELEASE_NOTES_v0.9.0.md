# AutoBuddy v0.9.0

> 模型级失败即时学习 + 换号重试、正向能力矩阵、后台日志去重、Buddy 徽章统一图标。

## 1. 模型级失败即时学习 + 换号重试

你提的需求很具体：**某个模型如果多个账号支持，就让多个账号同时参与并发调用；不支持的不要被选中** —— 那就不该出现 `model not found` 之类的报错。

问题是，模型级禁用黑名单一直是**事后学习**的：只有巡检跑过、或人工拉黑过的「账号 × 模型」组合才在册。**首次**命中不支持组合时，网关会把上游错误直接透传给客户端 —— 这就是报错的来源（实测 `gemini-3.5-flash`、`gpt-5.6-terra` 偶发 11102，因为只有部分账号有权）。

v0.9.0 补上闭环：

- 识别上游「该账号不支持该模型」的错误形状：状态码 400/403/404 + 错误码 `11102`/`11103` + 一揽子文案兜底（`service info not found`、`is only available for authorized` 等）；
- **立即写入 auto 拉黑**，下个请求起不再选中该组合；
- **自动换下一个账号重试**，上限 = 候选账号数（不设死数字，让「只有少数账号支持」时能把所有可能都试一遍）；
- 全部候选都失败，才把上游真实错误返回客户端 —— 不做假成功，也不编造「无账号」。

**重试安全边界**：只发生在「上游响应体尚未转发给客户端」的阶段。已经开始往客户端吐字节的请求不重试，避免上下文重复。流式与非流式两条路径都覆盖。

**限流/网络抖动/参数校验错误不参与重试与学习** —— 那些换号也解决不了，卷进来只会放大故障。

## 2. 正向能力矩阵（账号 × 模型 支持情况）

不只事后拉黑，还正向记录「某账号对某模型是支持的」。三个数据源共同维护：

- 请求成功（上游 200 且未换号）→ 记为**支持**；
- 上游拒绝 → 记为**不支持**；
- 巡检结果回填 → `available` 记支持、`unavailable` 记不支持。

`transient`（限流/超时）、`probe_defect`（参数被上游拒）、`restricted`（风控拦截）**一律不写** —— 那几类说明探测没拿到有效结论，写进矩阵会把探测侧的问题伪装成「模型不支持」，反而误伤好账号。

选号与换号重试时**先按矩阵优先挑「已知支持」的账号**，但只有在**确实存在**支持者时才收窄候选集 —— 避免矩阵过旧把整个账号池排除掉。

落盘 `model_capability.json`，带 5 秒读缓存，不增加每请求的读盘开销。

## 3. 后台日志去重

新增 `lprint()`：同一来源的相邻日志若与上一条**完全相同**，不再重复输出，只累计次数；等到出现**不同**的日志时，先补一行「上一条重复 N 次」再输出新行 —— 观测不断档，也不刷屏。

账号选号（`[pool]`）、账号轮换（`[rotate]`）、模型巡检（`[health]`）三处高频日志已切过去重输出。

## 4. Buddy 旅行徽章统一图标

此前「无 Buddy」用的是另一枚纸飞机，与领养后显示的图标**不是同一枚**，看起来像两种东西。

现在三态统一使用**官方 `plane-takeoff` 起飞飞机图标**（从官方前端 JS 中提取，保证同一枚），仅以「线型 + 颜色」区分状态：

| 状态 | 线型 | 颜色 | 含义 |
| --- | --- | --- | --- |
| 无 Buddy | 虚线 | 灰（`#94a3b8`） | 还没领养宠物伙伴 |
| 未旅行 | 实线 | 中性（muted） | 已领养，伙伴在家待命 |
| 旅行中 | 实线 | 主题色（primary） | 伙伴出门旅行 |

官方文案仍作为徽章文本保留（悬浮可见完整说明），只替换图标与配色，不改动官方状态语义。
