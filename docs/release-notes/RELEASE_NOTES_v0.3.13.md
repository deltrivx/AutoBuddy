## 方法：用 patched 二进制反查「还活着的」界面文案

补丁已把要移除的 JSX 整块换成 `null`，所以有个很好用的推论：

> **凡是在 patched 二进制里还能找到的中文界面文案，就一定不在已抹除区间内。**

把 `children` / `aria-label` / `placeholder` / `title` / `description` 里的中文文案全量抽出来（109 条），
再按桌面/CLI 关键词筛一遍，剩 7 处。逐个追查「打开入口是否已被抹除」后，只有一处是真问题。

## 1. 账号列表空状态引用了已移除的按钮（唯一真问题，已修）

```jsx
t === "ai" ? <>
  <p>暂无国际版账号。</p>
  <p>请确认本机已安装 {Ct}（客户端下载域名 {sF(t)}）并登录，
     再点击上方「导入本机国际版账号」；也可以直接「OAuth 登录」添加国际版账号。</p>
</> : "暂无账号。点击上方按钮导入本机账号或扫码登录。"
```

账号列表为空时就会渲染，却让用户去点**已经被删掉的**「导入本机国际版账号」/「导入本机账号」按钮；
而且「请确认本机已安装…」本身就是桌面端话术。

**修法**：

- 国际版那段含 `{Ct}` / `{sF(t)}` 两处 JSX 插值，正则跨不了嵌套 → 新增工具函数 **`_replace_call()`**，
  用 `_call_start_before` + `_scan_expr` 做括号配平定位，把整个 `<p>` 换掉。
- 国内版是纯字符串 → 等长改写。

新文案（都是容器里真实存在的入口）：

| 位置 | 新文案 |
| :--- | :--- |
| 国际版空状态 | 国际版账号请用上方「OAuth 扫码添加」或「导入备份」添加。 |
| 国内版空状态 | 暂无账号。请用上方「OAuth 扫码添加」添加。 |

## 2. 另外 6 处确认是死代码，不动

| 文案 | 宿主 | 结论 |
| :--- | :--- | :--- |
| `关闭 CLI 并切换` / `切换 CodeBuddy CLI` | 账号卡片里的 CLI 切换弹窗（`open:Ot!==null`） | 唯一入口是已被抹除的产品槽位按钮 → 不可达 |
| `将注入凭证并重启 CodeBuddy IDE` | IDE 切换 toast（`pi()`） | 同上 → 不可达 |
| `点击下方「打开完全磁盘访问」` | 权限引导弹窗 `AZ({open,...})` | **没有任何调用点**（唯一命中是定义本身）→ 不可达 |
| `在 Finder 中显示` | 导出弹窗的 `aZ()` / `iZ()` | 只在桌面分支设置 `v` 后才渲染；浏览器分支（`fn()` 为真）下载完直接关弹窗 → 不可达；响应层也已把它改写成「在文件管理器中显示」 |
| `客户端` | Rust 后端字符串表 / Token 表格列头 | 非前端残留 |

> 顺带确认了一个此前没查过的点：`fn()` 是**浏览器检测**
> （`return typeof window<"u" && !("__TAURI_INTERNALS__"in window)`，为真 = 非 Tauri）。
> 全量核对 5 处 Tauri 动态 import，只有 `aZ`（reveal in dir）没加 `fn()` 守卫，
> 但它的渲染条件只由桌面分支设置，容器里不会触发。
