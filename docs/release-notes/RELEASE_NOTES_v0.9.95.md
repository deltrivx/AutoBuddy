## 一、先回答你的问题：「500」到底是什么

**本地实测（24 个账号，权威）**：签到是 **100 积分/天**，没有任何 500。

```
daily_credit      = 100        ← 本期每日签到
total_credits     = 1800       ← 连签 18 天 × 100
streak_bonus      = 0 / 0 天    ← 本期连签奖励未激活
week_progress     = 6/7 天
活动 = Buddy加油站 第10期（09-30 ~ 10-31）
```

**联网交叉验证（Tavily 多来源）**：500 有三种可能，**都不是签到每日额度**：

| 出处 | 内容 | 判定 |
|---|---|---|
| 免费版月赠 | 每月固定送 500 分，自动到账 | ✅ 真实，但是月赠不是签到 |
| 体验专家团任务 | 500 积分**一次性**任务奖励 | ✅ 真实，属成长任务 |
| 往期限时活动 | 「每日150 + 额外500限时速领」 | ⚠️ 往期活动，本期不是 |

另外我们自己的台账里就有原文——**「签到连签5天，累计500」**。这正是歧义来源：500 是连签 5 天的**累计值**，不是单日额度。

**结论**：500 大概率是记混了（累计值 vs 单日值），或指月赠/一次性任务。当前签到确定 100/天。

## 四、还挖出一个更深的 bug

排查时发现：即使有了工具，助手**有时仍然只复述工具原文**，不做任何解读。

**根因**：`step-5-preview` 在 `tool_choice=none` 下**仍会返回 tool_calls 且 content 为空**——三次抽样两次中招，正文全跑进 `reasoning_content` 里。旧代码只在「请求抛异常」时才退回无 tools 重试；模型规规矩矩返回 tool_calls 不算异常，于是 final 一直是空 → 走工具原文回落 → 用户看到一堆未经解读的字段堆砌。

这正是你看到的「答非所问」的直接成因。

**修复**：第二轮改为按顺序试两种 payload，谁先给出「非空正文且不再调工具」就用谁：

```
① 带 tools + tool_choice=none   （首选，上下文仍有工具声明）
② 完全不带 tools                （彻底断掉再调工具的念头）
```
