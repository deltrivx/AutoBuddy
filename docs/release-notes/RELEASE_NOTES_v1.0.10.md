## 一、账号搜索框：档位切换行右端 + 官方尺寸对齐

位置从「账号卡片上方」挪到「国内版 / 国际版」档位切换的**同一行、右端**。

定位走「文本 + 结构」双判据，不依赖易变的 class 名：

1. 先找 `aria-label` 含「档位」的 tablist（官方自己标了语义，最稳）；
2. 找不到再退回到「含 国内版 / 国际版 两个按钮」的容器。

找到后把档位容器（官方 `flex flex-col mt-4 gap-0`）改成横向 flex + 两端对齐，搜索框追加到行尾，自然落在同一行的最右端。

尺寸逐像素对齐官方切换组（实测官方 computed style 后照抄）：

| 项 | 官方档位切换组 | 搜索框 |
| :--- | :--- | :--- |
| 容器高度 | h-9 = 36px | 36px |
| 控件高度 | h-7 = 28px | 28px |
| 圆角 | rounded-lg = 10px（按钮 rounded-md 同值） | 10px |
| 字号 | text-xs = 12px | 12px |
| 字重 | font-medium = 500 | 500 |
| 底色 | 未选中按钮白底 + 1px 边框 | 白底 + 1px 边框 + 轻投影 |

**一个容易漏的坑**：tablist 自身有 `padding: 4px`，里面的按钮实际落在 `y+4`；搜索框若用 `align-items: center` 会比档位按钮高 4px，肉眼一眼能看出不在一个水平线上。这里用 `padding-top: 6px` 抵消，实测垂直偏差 1px（同一水平线）。

移动端（≤640px）搜索框退到下一行、全宽，不与切换组互相压扁。

## 二、每日任务开关：三个独立开关、独立持久化

改完后，每日任务页里与签到/执行相关的开关一共三个，语义互不重叠：

| 开关 | 配置字段 | 含义 |
| :--- | :--- | :--- |
| 启动补签 | `checkin_enabled` | 容器启动时核验一次服务端状态，未签到账号自动补签 |
| 启用签到调度 | `checkin_schedule_enabled` | 定时跑「签到轮」（只跑每日签到） |
| 启用任务调度 | `task_schedule_enabled` | 定时跑「任务轮」（除签到以外的全部任务） |

三个字段在后端 `DEFAULT_CONFIG` 里分开定义、`ConfigBody` 分开接收、`/api/wb-daily/config` 分开读写，调度循环里签到轮与任务轮各自判断各自是否到期（各自的时间戳 + 各自的间隔），任一边单独停用不影响另一边。

原先「启用自动签到」混在「执行模式与账号保活」卡里，和两个调度开关并列出现，容易被读成同一个东西；现更名为「启动补签」并移入签到调度卡，三个开关在一处、名字不重样。

## 三、账号签到与凭据：补背景框

这一块此前**没有卡片外框**。根因是 innerHTML 的 div 层级写漏了一层闭合，它被踢出所属卡片、成了 `wb-daily-wrap` 的直接子元素 —— 既没有白底 / 1px 边框 / 16px 圆角，也没有卡片内边距，看起来像一块没框的内容贴在页面上。

现在把它重新包回 `.wb-api-card`，与同页「任务清单 / 任务记录 / 执行记录」用**同一个**圆角、边框、底色、内边距，左右边缘严格对齐（实测同为 x=147、宽 1116）。

顺带修掉一个隐藏雷：innerHTML 里原本多出的那个 `</div>`，在这一行被包回卡片后会反过来把 `wb-daily-wrap` 提前关掉，导致整页的作用域样式（按钮尺寸、输入框尺寸、表格规格等）全部失效。现已去掉多余闭合，div 嵌套平衡。

## 四、设备指纹与 UA：动态池化隔离，覆盖新账号

v1.0.9 已做存量账号的独立指纹（UUIDv5 持久化），本轮补两点。

### 新账号在哪一步触发分配

两处，缺一不可：

1. **网关启动时**（`main.py` lifespan 钩子）：给账号池里全部账号补齐指纹 —— 存量账号原样复用，新加入的账号当场分配并落盘；
2. **每日任务收集参与账号时**（`wb_daily.build_account_store`）：账号是**随时**加进来的（扫码 / OAuth 授权后立刻出现在 `accounts.json`），启动钩子跑完之后新加的账号靠这一处兜住。

两处都调同一个 `ensure_account_fingerprints(accounts)`，返回 `{"total": n, "created": m}`，只对库里没有的账号创建，重复调用是幂等的（第二次 `created = 0`）。

### 池化去重怎么做

分配前先扫全库，收集四套「已占用」集合：`machineId`、`MAC`、硬件档位四元组 `(os, osVersion, cpuCores, memorySize)`、`UA`。新账号的每一项都不得落在对应集合里：

- **machineId / MAC**：由账号 key 稳定派生，撞车则加盐重取；
- **硬件画像 + UA**：先用 key 哈希定位一个起始档位（同一账号重试结果稳定），再向后顺延，跳过已占用的档位与 UA；
- **池容量耗尽**（账号数 > 档位数）：保留档位，按 Chrome 的 build/patch 段顺延产出唯一 UA，绝不返回别人已用过的组合。

实测 30 个账号：`machineId` / `sessionId` / `mpMachineId` / `webMachineId` / `MAC` / `UA` 六个维度**全部唯一**；存量账号画像不漂移；重复调用幂等。

### 顺带修掉一个静默失效的 bug

`_bump_ua` 旧实现先 `build += step`，再 `replace` 那个**已经自增过**的版本号串 —— old 串在原 UA 里根本不存在，`str.replace` 静默返回原串。结果是「bump 过的 UA」和原 UA 一模一样，池化去重完全失效：实测 30 个账号 UA 只有 12 个唯一、重复 18 次。多账号共用同一个 UA 正是上游并案标记最显眼的特征。现 `replace` 用原始版本号作 old 串、自增后的作 new 串。

### 下游零改动

`workbuddy_daily.py` 仍按 `uid` 调 `get_or_create_fingerprint(uid)` 取画像，签名与返回结构都没变 —— 池化隔离全部发生在指纹库写入侧，桌面事件与 Web 上报的取用逻辑不用动。
