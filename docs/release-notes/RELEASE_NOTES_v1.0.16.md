# 异常账号卡片：登录提醒区域变小，内框高度对齐

> 本版只做 UI 尺寸微调。v1.0.9 定下的异常态结构（顶部外框只留右侧两个按钮 +
> 功能收纳、内框含重新登录提示 + 按钮区 + 模型区、灰化不可操作）**全部保留**，
> 一个结构都没动。

## 调整前实测数据

同一张异常卡与一张正常卡，同为 334px 内容宽，PC 端逐项量：

| 区域 | 异常卡 | 正常卡 | 差额 |
| :--- | ---: | ---: | ---: |
| 登录提醒块 | **86px** | — （对应位置是积分包内容区 **65px**） | **+21px（反了）** |
| 模型区标题行 | **18px** | **24px** | -6px |
| 模型区总高 | **330px** | **336px** | -6px |
| section 总高 | **519px** | **575px** | -56px |

两个问题从这张表直接读出来：

1. **登录提醒块比它替代的正常区域还高。** 它替换的是官方那个 401 错误块，位置对应正常卡的积分包内容区（65px）。结果提醒块做到 86px —— 比要替代的内容高 21px，一眼突兀。根因是 CSS 里写了 `min-height: 80px`，实测这 80px 就是钉住高度的唯一原因。
2. **内框高度没对齐。** 异常态没有「已禁用 / 巡检」徽标和「全部恢复」按钮，模型区标题行从 24px 塌到 18px，模型区总高跟着从 336px 掉到 330px，section 整体少 56px。

## 调整后实测数据

| 区域 | 调整前 | 调整后 | 正常卡基准 |
| :--- | ---: | ---: | ---: |
| 登录提醒块 | 86px | **53px** | 65px（对应位置） |
| 模型区标题行 | 18px | **24px** | 24px |
| 模型区总高 | 330px | **336px** | 336px |

提醒块从 86px 降到 53px：比正常对应区小 12px，比原来小 33px。

## 具体改法

**登录提醒块**（`.wb-official-relogin`）：

- 去掉 `min-height: 80px`（唯一钉高度的东西）
- padding `12px 14px` → `5px 10px`
- gap `4px` → `1px`
- 标题 `13px/1.5` → `11px/1.3`
- 说明 `11.5px/1.6` → `10px/1.35`
- 新增 `margin-top: 12px`，顶替被隐藏的官方第二块（17px 高 + 12px 上间距），让两张卡的间距节奏一致

**内框高度对齐**（模型区）：

- `wbApplyReloginDisabled()` 就地量一张**同页正常卡**的模型区实际高度，搬过来设为 `min-height`
- 不写死像素：PC 约 336px、移动端各自适配，内容变了也跟着变
- `wbApplyReloginEnabled()` 恢复登录时一并撤掉该高度 —— 否则账号恢复后卡片仍钉着一个过期快照
- 模型区标题行另给 `min-height: 24px`

**移动端**：

- `.wb-pool-relogin-desc` 限 2 行（`-webkit-line-clamp: 2`）。窄屏内容宽约 310px，同样文案可能比 PC 多折一行，一旦多折整块就被撑高，「比正常区域小」在手机上会失效。

## 为什么 section 总高不强行填平

正常卡顶部有「积分/用量标题行 + 副标题行 + 积分包内容区」共 136px（含间距），异常卡这三块被隐藏，只留一枚登录提醒块。

这个差额**没有硬填**。异常卡没有积分数据可显示，填 136px 空白进去是假的。只把**同名区域**逐项对齐（标题行、模型区），让两张卡并排时下沿齐平。

## 回归保护

`_test_v109_features.py` 新增 14 项契约断言，分三组：

- **四校结构契约**：顶部外框 badge 隐藏且不误伤右侧两个按钮、内框三件套齐全、灰化含 `grayscale` + `pointer-events: none`、提示块 `flex: 0 0 auto` 不撑满内框、提示块不在 header 里
- **尺寸契约**：无 `min-height: 80px`、原始 padding 不得残留、标题与说明的字号行高确实收紧了
- **对齐契约**：内容驱动而非写死像素、恢复登录时撤掉高度、移动端限 2 行

改坏任何一条，测试立刻红。
