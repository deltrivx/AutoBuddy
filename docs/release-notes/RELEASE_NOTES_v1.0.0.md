## 一、任务自动化

### 任务巡检（中断自动恢复）

任务被中断（容器重启 / 被 kill / 超时）后不再等下一轮调度（默认 12h，中断当天的剩余账号要等到第二天才跑）。新增独立巡检周期：

| 项 | 值 |
| :--- | :--- |
| 默认周期 | 60 分钟 |
| 可配范围 | 5 – 1440 分钟 |
| 配置位置 | 每日任务页 → 任务巡检卡片 |

巡检间隔小于执行间隔才生效，保存时若违反会明确提示「巡检不会生效」。

### 签到 / 任务调度拆分

原「自动签到与调度」是一张混合卡，签到与任务共用一个开关、一个间隔、一个 `last_run_at` —— 跑完签到会把任务轮的下次执行时间也推后，两边相互影响。

现拆为三张独立卡片：**签到调度** / **任务调度** / **任务巡检**，各管自己的开关、间隔、上次与下次执行时间。执行时按轮次类型给上游脚本传不同任务过滤：

```bash
# 签到轮：只跑每日签到
workbuddy_daily.py --no-desktop --tasks checkin

# 任务轮：跑除签到以外的全部
workbuddy_daily.py --no-desktop --skip-tasks checkin
```

### 断点续跑 + 增量落盘

中断后的下一轮自动跳过已跑完的账号，从剩余账号继续。上游脚本按账号串行执行，中断点之前的账号当天任务已真做完、明细也已落库（积分 / 连签 / 等级 / 任务台账），收益天然已结算。

任务执行期间每 20 秒落一次盘 —— 面板能实时看到「这一轮已跑完哪几个账号」，被强杀时最后几十秒的进度已在库里。

## 五、智能助手

### 新增 `get_checkin_activity` 工具

返回签到活动实时字段（每日积分、连签/累计、本周进度、连签奖励、活动周期）。此前 32 个工具没有一个读签到活动数据 —— 问「签到给多少分」只能拿规则表常量硬答。

### 「数字对不上必须双查」规则

用户报出的数字与数据源不一致时，禁止二选一就下结论：本地实时字段 → 联网官方规则 → 都查完再答，明确说清本地值、用户那个数可能对应什么（月赠 / 一次性任务 / 往期活动 / 累计值被误当单日值）、结论以哪边为准。

### 修掉「答非所问」的直接成因

模型在 `tool_choice=none` 下**仍会返回 tool_calls 且 content 为空**（正文全跑进 reasoning_content）。旧代码只在请求抛异常时才重试 —— 模型规规矩矩返回 tool_calls 不算异常，于是 final 一直为空，回落成工具原文堆砌。现改为双变体重试。实测同问题连跑 5 次，答非所问 0/5。

## 七、数据口径修正

- **今日消耗 KPI**：「昨日消耗」改为「今日消耗」，取 `summary.usageToday`（已由 `_reconcile_official_usage` 校准）
- **账号池总积分徽标改为净值**：原先是 usageToday（纯消耗），与旁边「今日消耗」卡一模一样；现改为「今日获得 − 今日消耗」
- **日报「昨日签到积分」恒为 0**：日报绕过了 HTTP 层的签到合并，而该合并是页面签到积分的唯一来源
- **日报「昨日调用」翻倍**：两个 source 扫同一批文件却直接相加；改为取每日最大值
- **签到通知重复推送**：`_notify_checkin_once` 挂在账号完成处不看轮次类型，任务轮每被拉起一次就发一次；现只由签到轮发送，并加 6 小时跨轮次时间窗
- **通知内容去重**：同一场景连续两次推送内容完全相同时自动跳过

## 八、新增部署脚本

`scripts/deploy.sh`：部署前软中止正在执行的每日任务（等最多 30s），再重启容器 —— 比直接 `docker restart` 硬杀干净，任务走正常收尾路径（落库 + 标记 aborted），巡检稍后自动从剩余账号续跑。`--sync` 额外同步 `gateway/*.py` 并清陈旧 `__pycache__`。
