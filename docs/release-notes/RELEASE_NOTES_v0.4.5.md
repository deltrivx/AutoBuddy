## 一、修复：缓存命中率恒为 0

网关此前从不读上游随响应返回的用量：输入与输出都按**字符数估算**（约 3.5 字符算 1 个 token），
缓存命中数没有采集、恒定记为 0。命中率 = 命中数 ÷ 输入，分子恒为 0，结果自然恒为 0。

现在改为直接采用上游的**真实用量**，并采集命中缓存与写入缓存的 token 数。

| 统计项 | 之前 | 现在 |
| :--- | :--- | :--- |
| 输入 / 输出 token | 按字符数估算 | 上游实测值 |
| 缓存命中数 | 恒为 0 | 上游实测值 |
| 缓存命中率 | 恒为 0% | 命中数 ÷ 输入 |

三点需要说明：

- **历史记录里没有缓存明细**，一律按「全部未命中」计入。因此命中率会随着新的调用逐步上升，
  不是升级完就立刻到一个稳定值 —— 老数据里那部分谁也无法回溯。
- **同一段对话统计出的 token 数会与之前不同**（通常更高，中文按字符数折算一向偏低）。
  这是口径变准了，不是用量涨了。
- **拿不到用量时仍回退到字符估算**，并把命中记为 0（例如调用方中途断开、上游末帧没到）。

顺带一提，采集用量**不需要往请求里加任何参数** —— 上游本来就会在响应的末帧带上它。
前两个版本连续踩过「多加一个可选参数被上游校验拒掉」的坑，这一版不再重复。

## 二、变更：版本号合并为一套

以前有两条并行的版本线，且都显示给用户看：

| | 之前 | 现在 |
| :--- | :--- | :--- |
| 设置页「关于」徽章 | `v1.8.0`（网关内部版本） | `v0.4.5` |
| GitHub 发布标签 | `v0.4.4` | `v0.4.5` |
| 镜像 tag | `v0.4.4` | `v0.4.5` |

现在**只有一个号**：网关报出的版本 = GitHub 发布标签 = 镜像 tag。

为保证它不会再次错位，构建流水线新增一道校验：网关的版本常量必须与更新日志最新一段、
发布说明文件对得上，**对不上直接构建失败**。

## 三、变更：设置页「关于」重新排版

- **去掉「容器镜像」一块**，升级方式属于文档，镜像名与版本号本来就是同一件事。
  项目主页、更新日志、发布版本、问题反馈四个入口保留。
- **「数据目录与端口」改为对齐的两列**，分别列出三个地址：

  | 项 | 内容 |
  | :--- | :--- |
  | 数据目录 | 账号、密钥与模型策略所在路径，可一键复制 |
  | 控制台 | 浏览器打开这个地址 |
  | 网关 API | 程序调用填这个地址（OpenAI 兼容） |

## 四、新增：三道构建期检查

| 检查 | 守的是什么 | 不检查会怎样 |
| :--- | :--- | :--- |
| 版本号一致性 | 网关报出的版本必须与更新日志、发布说明对得上 | 面板与发布页各说各话，用户只能猜 |
| Token 用量统计 | 缓存字段解析、跨数据块的流式采集、命中率聚合与边界 | 数字悄悄变回 0，没人发现 |
| 界面渲染冒烟 | 注入到前端的脚本必须能渲染出每个面板 | 面板整块**静默消失**：无报错、无日志，页面只是「少了一块」 |

第三项是这一版才补上的：注入脚本里的一个变量名遮蔽，就会让某块面板再也不出现，
而页面本身看起来完全正常。现在这类问题会在构建阶段就被拦下。

## 不改变的行为

账号管理、自动签到、账号池调度（并行轮询 / 手动首选 / 请求级指定账号）、
模型别名路由、模型标签的手动禁用、模型可用性巡检的开关与判定规则 —— **全部保持不变**。

对外提供的 OpenAI 兼容接口形态不变（仅当上游返回了缓存明细时，多带几个可选的用量字段）；
请求参数**没有增删**，调用方的行为不受影响。
