## 🐞 修复：手动固定 / 指定账号看起来「没生效」

**现象**：把某个账号设为「首选」，或用请求头指定账号发请求后，
状态接口里的「最近使用账号」始终显示成另一个账号，像是配置被忽略了。

**根因**：选账号有**三条路径**（自动轮询 / 手动固定 / 请求指定），
但只有**自动轮询**那条会记录结果。

于是走「请求指定」或「手动固定」时，该字段一直停留在上一次自动分配的结果，造成误判。

**修复**：三条路径统一记录账号与来源，并新增「来源」字段，
可直接看出本次选择来自请求指定、手动固定还是自动轮询。

## WebUI

账号卡片控制条上为「最近一次真实调用所用账号」增加 `最近调用` 虚线标签，
便于直观确认账号池是否按预期分配。

## 验证

容器内真实调用验证：

- 手动固定稳定命中指定账号；
- 请求头单次覆盖生效；
- 已停用账号被指定时返回 `409`；
- 自动模式连续 5 次调用分摊到 5 个不同账号。

## 升级方式

```bash
docker pull ghcr.io/deltrivx/workbuddy-switch:v0.3.5
docker pull ghcr.io/deltrivx/workbuddy-switch:latest
```

> Unraid 请通过容器模板重建，**不要手工拼接 `docker run`**。
> 数据目录不变（`/data`），升级不会动到账号数据。

## 不改变的行为

账号的分配规则本身没有变化，只是把「用哪个账号」这件事**如实记录下来**。
