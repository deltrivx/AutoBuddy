## 需求

这一版来自几处使用中的别扭之处，都是「看得见但说不清」的那类问题：

- **Token 统计页的「缓存命中率」永远是 0**，无论实际命中多少，指针都不动；
- **版本号有两套** —— 设置页显示 `v1.8.0`，发布页写 `v0.4.4`，
  同一份东西两个号，没法判断自己跑的是不是最新；
- 设置页「关于」里**镜像地址是多余的**，而**数据目录与端口挤在一行、换行后错位**。

第一项是数据没采，后两项是展示没想清楚。这一版一并收尾。

---

## 一、修复：缓存命中率恒为 0

**症状**：统计页上 Token 总数、输入、输出都有数，唯独「缓存命中率」一直是 0%。

**原因**：命中率本身没算错，是**喂进去的数据是空的**。网关此前：

1. 从不读上游随响应返回的用量，输入与输出都是按**字符数估算**的（约 3.5 字符算 1 个 token）；
2. 缓存命中数没有采集，恒定记为 0。

命中率 = 命中数 ÷ 输入，分子恒为 0，结果自然恒为 0。

**修复**：改为直接采用上游随响应返回的**真实用量**，并采集命中缓存与写入缓存的 token 数。

| 统计项 | 之前 | 现在 |
| :--- | :--- | :--- |
| 输入 / 输出 token | 按字符数估算 | 上游实测值 |
| 缓存命中数 | 恒为 0 | 上游实测值 |
| 缓存命中率 | 恒为 0% | 命中数 ÷ 输入 |

三点需要说明：

- **历史记录里没有缓存明细**，一律按「全部未命中」计入。因此命中率会随着新的调用
  逐步上升，不是升级完就立刻到一个稳定值 —— 老数据里那部分谁也无法回溯。
- **同一段对话统计出的 token 数会与之前不同**（通常更高，中文按字符数折算一向偏低）。
  这是口径变准了，不是用量涨了。
- **拿不到用量时仍回退到字符估算**，并把命中记为 0（例如调用方在中途断开、
  上游的末帧没到）。不知道就是不知道，不编一个数出来。

顺带一提，采集用量**不需要往请求里加任何参数** —— 上游本来就会在响应的末帧带上它。
这一点很重要：前两个版本连续踩过「多加一个可选参数被上游校验拒掉」的坑，
这一版不再重复。

## 二、变更：版本号合并为一套

以前有两条并行的版本线，且都显示给用户看：

| | 之前 | 现在 |
| :--- | :--- | :--- |
| 设置页「关于」徽章 | `v1.8.0`（网关内部版本） | `v0.4.5` |
| GitHub 发布标签 | `v0.4.4` | `v0.4.5` |
| 镜像 tag | `v0.4.4` | `v0.4.5` |

现在**只有一个号**：网关报出的版本 = GitHub 发布标签 = 镜像 tag。
你在 Releases 里看到的那个版本，就是面板上显示的那个。

为了保证它不会再次错位，构建流水线新增了一道校验：网关的版本常量必须与更新日志里
最新一段、发布说明文件对得上，**对不上直接构建失败**。这类问题靠人记是记不住的。

## 三、变更：设置页「关于」重新排版

- **去掉「容器镜像」一块**。升级方式属于文档，而镜像名与版本号本来就是同一件事，
  不必在面板上占两行重复一遍。项目主页、更新日志、发布版本、问题反馈四个入口保留。
- **「数据目录与端口」改为对齐的两列**，分别列出三个地址：

  | 项 | 内容 |
  | :--- | :--- |
  | 数据目录 | 账号、密钥与模型策略所在路径，可一键复制 |
  | 控制台 | 浏览器打开这个地址 |
  | 网关 API | 程序调用填这个地址（OpenAI 兼容） |

  此前路径与端口挤在同一行，路径长、端口短，一换行就对不齐；
  改为两列网格后标签列固定宽度，天然左对齐。

## 升级方式

```bash
docker pull ghcr.io/deltrivx/workbuddy-switch:v0.4.5
docker pull ghcr.io/deltrivx/workbuddy-switch:latest
```

- **Unraid**：走容器模板重建（在 Docker 页面选中该容器 → 编辑 → 应用），
  不要手工拼接 `docker run`。数据目录不变，账号、密钥与模型策略都不受影响。
- 升级后打开设置页，最底部的「关于」即可核对版本号是否与发布页一致。

## 不改变的行为

账号管理、自动签到、账号池调度（并行轮询 / 手动首选 / 请求级指定账号）、
模型别名路由、模型标签的手动禁用、模型可用性巡检的开关与判定规则 ——
**全部保持不变**。

对外提供的 OpenAI 兼容接口形态不变（仅当上游返回了缓存明细时，多带几个可选的用量字段）；
请求参数**没有增删**，调用方的行为不受影响。
