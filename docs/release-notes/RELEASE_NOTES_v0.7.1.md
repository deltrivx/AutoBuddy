# AutoBuddy v0.7.1

> 修复 v0.7.0 引入的注入 JS 语法错（每日任务页布局塌陷），并补全账号卡片缺失的三个操作。

## 1. 每日任务页布局塌陷 —— 是注入 JS 的语法错

### 根因
v0.7.0 拼接注入字符串时多写了两个加号：

```javascript
'</div>' + +        // 两处
```

这是**硬语法错误**。浏览器解析到它就直接抛 `SyntaxError`，**整段注入脚本一行都不执行** —— 所有注入面板一起消失、页面布局塌掉。

### 为什么当时测试全绿还是发出去了
- `py_compile` 只看 `web_proxy.py` 本身，里面装的是**字符串字面量**，拼出来的 JS 语法错它完全看不出
- 面板渲染测试依赖 node；这道门禁当时不存在

### 修复
- 修掉两个 `+ +`
- **给测试套件加上 `node --check` 门禁**（`_test_webui_panels.py` 的 `check_js_parses`）：注入 JS 语法不通就**直接失败**，并打印出错行。这类 bug 再也上不了 CI

## 2. 账号卡片补齐三个操作

官方卡片的「更多账号操作」菜单有三项，但它们调用的是**桌面版后端的路径**，容器网关并未实现 —— 点下去只有 404/500，属于「按钮在、功能没有」。

现在接到网关**真实实现**的接口上，走同一份账号数据，不是另画一套按钮充数：

| 按钮 | 接口 | 行为 |
|---|---|---|
| **刷新 Token** | `POST /refresh-token` | 用 RT 换新 AT 并写回账号文件，按 JWT 的 `exp` 同步更新 `expiresAt` |
| **手动签到** | `POST /wb-daily/run` | 复用每日任务服务，不另开一条签到路径 |
| **删除账号** | `POST /delete` | 删除账号，并清理其模型禁用策略与停用记录（免留孤立条目） |

另新增 `GET /export-accounts` 与 `POST /import`（合并式导入，**不删除**现有账号），供后续备份入口使用。

### 职责划分
- **账号池控制条** = 这个账号要不要参与 API 调用（轮询层面）
- **三个新按钮** = 对这个账号本身的维护动作（凭据 / 签到 / 删除）

### 写回的安全处理
- 采用「先写临时文件再原子替换」，避免中途中断写坏账号文件
- 保留原有属主与权限，不因覆写而改变
- **同时写官方那份文件**（`/data/.wb-switch/accounts.json`）——只写本地副本会重现「改了却不生效」

## 设计原则

**门禁要盯住真正会出错的那一层。** Python 语法检查通过，不代表拼出来的 JS 能跑。测试覆盖面要跟着「错误实际发生的层级」走。

**按钮必须接到真实接口。** 补 UI 不等于补功能；没有后端支撑的按钮，只是在制造下一个「点了报错」。
