# AutoBuddy v0.9.5

> 取消昵称、头像预览独立放大、CHANGELOG 与 README 规范化。

## 1. 取消昵称，显示名以用户名为准

### 问题

系统里同时存在两套「显示名」：登录**用户名**，以及可在设置页修改的**昵称**。
两者并存带来三个后果：

- 「我是谁」有两种答案 —— 右下角用户球显示昵称，设置页用户名栏却显示另一个值；
- 用户球浮窗需要在昵称下再补一行 `@用户名`，因为单靠昵称无法定位到实际账号；
- 修改用户名的逻辑里要额外判断「昵称是否仍是旧用户名」，以此决定要不要跟着改，
  这类联动规则本身就是两套显示名带来的额外复杂度。

### 处理

昵称整体取消，显示名一律取登录用户名：

| 位置 | 变更 |
| :--- | :--- |
| `/api/auth/profile` GET | 不再返回 `nickname` |
| `/api/auth/profile` PUT | 请求体移除 `nickname` 字段，仅保留 `avatar` |
| `/api/auth/status`、`/api/auth/login` | 不再返回 `nickname` |
| 设置页「账号资料」 | 「昵称」输入框移除，按钮改为「保存头像」 |
| 「修改资料」弹窗 | 同上，仅保留头像选择 |
| 右下角用户球 | 显示名取 `username`；浮窗中重复的 `@用户名` 行移除 |

`db.get_nickname` / `set_nickname` **保留但标记为遗留**，不再被任何代码调用，
仅用于兼容旧数据与旧版本调用方。

> 注：账号池中每个账号的 `nickname` 来自上游账号数据（账号自身的昵称或邮箱），
> 与用户资料昵称无关，不受本次改动影响。

## 2. 头像预览独立成行并放大

### 问题

头像区原结构为「左侧 52px 预览图 + 右侧竖排选择器」。预览图偏小且被挤在一侧，
选择头像时难以判断实际效果。

### 处理

```
修改前                          修改后
┌──────────────────────┐       ┌──────────────────────┐
│ [52px] ◯◯◯◯◯◯◯⊕    │       │        (88px)        │
│                      │       │   ◯◯◯◯◯◯◯⊕        │
└──────────────────────┘       └──────────────────────┘
```

- 预览图由 52px 提升至 **88px**，加 2px 描边与投影；
- 头像区改为纵向布局，**预览居中独占一行**，选择器整行排在下方并居中；
- 上传按钮维持上一版形态（网格内最后一枚圆钮）。

## 3. CHANGELOG 规范化

### 问题

对照 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/) 检查，发现三处不合规：

1. **自造分类标题**：`### 优化`、`### 设计边界` 等，规范只允许六类
   （新增 / 变更 / 废弃 / 移除 / 修复 / 安全）；
2. **版本摘要句被当作分类标题**：v0.6.x 起多个版本把「这个版本做了什么」的整句话
   写成 `### 标题`，与真正的分类标题混在同一层级；
3. **摘要注释机制中断**：`<!-- summary: … -->` 自 v0.5.11 起不再书写，
   而 `scripts/gen_releases.py` 依赖它生成版本索引摘要 —— 缺失时回退取第一个
   `###` 分类标题，于是 **RELEASES.md 的「更新摘要」列长期只显示「新增」「修复」
   「移除」这类分类名**，索引失去意义。

统计：最近 25 个版本中，19 个分类不合规；40 个版本有摘要注释，v0.5.11 之后全部缺失。

### 处理

- CHANGELOG 顶部新增分类规范表与摘要注释书写要求，明确「不得自造分类名」；
- v0.9.4 的 `### 优化` 并入 `### 变更`；
- 为 v0.8.0 / v0.8.1 / v0.8.2 / v0.9.0 / v0.9.1 / v0.9.3 / v0.9.4 补回摘要注释；
- 重新生成 `RELEASES.md`，摘要列恢复为可读的一句话说明。

## 4. README 重写为规范化文档

### 问题

上一版 README 偏营销文案风格：emoji 装饰标题、痛点表格中夹带语气词、
致谢段落写成抒情长句。信息本身不算错，但不符合技术项目文档的阅读预期 ——
读者需要的是**能快速定位的精确信息**，而非说服性文字。

### 处理

- 移除全部 emoji 标题与煽动性表述，语气改为陈述式；
- 结构调整为：功能 / 快速开始 / 配置 / 接入 / 运维 / 实现说明 / 许可 / 致谢；
- 新增**「实现说明」**一章，包含：
  - 目录结构与各文件职责；
  - **界面注入方式**（反向代理注入脚本、JS 文案替换、二进制补丁，
    以及注入脚本语法错误会导致区块静默消失、因此有 `node --check` 门禁）；
  - **构建约束**（上游版本必须锁定，锚点失配需人工复核，不在本地构建）。
- 功能描述保留全部技术细节，但删除背景铺垫与口语化表述。
