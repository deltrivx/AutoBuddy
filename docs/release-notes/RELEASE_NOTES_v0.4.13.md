## 一、修复：检测提示改说人话

正常账号的提示此前长这样：

> 账号正常（用一个不存在的模型名试；上游如实回应「该模型不存在」，说明它已认下这张凭据）

后半段是**探测手段**——我们怎么测的。但摆在结论旁边，读起来就变成了「有个模型
不存在」，好结论被读成故障。

现在提示只讲两件事：**账号能不能用**、**为什么不能用**。

| 结论 | 提示 |
| :--- | :--- |
| 正常 | 账号正常，可以放心使用 |
| 风控 | 账号被上游风控拦截，暂时用不了 |
| 过期 | 登录已过期，请重新登录 |
| 未测出 | 这次没测出结果，请稍后重试 |

正常账号就这一句，后面不再跟任何技术细节。出错时才补上原因与建议。
探测手段仍然保留在接口里，供排查时查看，但**不再出现在提示里**。

## 二、修复：风控直接说风控

账号被上游风控或内容安全拦截时，提示原本是「凭据有效，但请求被上游拦截」。
这句话要求用户理解「凭据」与「请求」的区别，才能判断该怎么处理。

现在直接说「账号被上游风控拦截」——「风控」是用户能对上号的词，它明确指向
「账号被平台限制了」，而不是让人怀疑工具或网络出了问题。同时保留说明：
重新登录没有用，需要检查账号状态。

## 三、修复：风控账号纳入自动停用

巡检此前只停「凭据失效」的账号。被风控的账号凭据是好的，于是继续参与轮询 ——
而它发出的请求会被上游一律拦下，结果就是**持续失败**，并把同账号下所有模型的
探测结果一并污染成失败。

现在风控与凭据失效同等处理：一并自动停用，并列入受限清单，界面可见。

## 四、修复：只有账号恢复正常才自动放回轮询

上一版的风控账号停用之后，没有任何机制把它放回来 —— 即使账号已经恢复，
也只能人工处理。这一版补上账号级自动启用，判据是**账号级探测结论为正常**。

这里的关键是判据**不能**选「名下某个模型探测通过了」：账号整体被风控时，
个别模型偶然通过不代表它能用。放回的依据必须是账号级结论。

人工停用的账号仍然受保护，巡检无权替人放开。

## 五、修复：账号被风控时模型不再被自动启用

同一个道理也适用于模型级。模型自愈此前只看模型维度，账号整体被风控时，
若某个模型这一轮偶然探测通过，它会被放回轮询 —— 下一轮又失败，来回抖动。

现在账号处于风控状态期间，冻结该账号一切自动启用。

## 变更

巡检结果新增 `accountsEnabled` 字段，列出本轮被自动放回轮询的账号。
此前只看得到账号被停用，看不到它何时恢复。

## 不改变的行为

- 账号有效性的判定标准不变，本轮不改任何结论，只改表述与轮询归属。
- 手动禁用的模型与手动停用的账号仍受保护，自动流程不会推翻人的决定。
- 网络抖动的账号（transient）不下手停用 —— 一次性问题，误停的代价大于漏停。
- 巡检默认仍为关闭状态，间隔与账号范围的配置方式照旧。
