> 修复通知里「剩余积分 > 总积分」的口径悖论；菜单按钮改为四项积分统计口径。

## 用户反馈

> 菜单交互依然没有落地，最近两次通知消息剩余积分大于总积分

## 修复 1：通知积分口径悖论

实测（容器内）：

| 口径 | 来源 | 实测值 |
|---|---|---|
| 账号池**剩余**积分 | `credit_floor._latest_balances()` 实时快照合计 | **40,661.7** |
| **累计任务**积分 | `db.summarize_wb_daily_credits().totalCredits`（台账累计获得） | **29,900.0** |

两者**量纲不同**（实时余额 vs 累计获得），却并列成「剩余 / 总」——必然出现「剩余 > 总」。

改为各自带明确归属，不再并排比较：

- ②签到成功：`本次签到积分 / 账号池剩余积分 / 累计任务积分`
- ③任务成功：`本次任务积分 / 累计任务积分`
- ①每日报告：`累计任务积分 / 账号池剩余积分`

## 修复 2：菜单按钮口径

`AB_ACCOUNTS`（账号余额）此前走到旧分支返回 23 个账号的逐条余额长列表。

改为与面板一致的**积分统计顶部四项**：剩余积分 / 今日消耗 / 近 7 天消耗 /
本月消耗。
