# AutoBuddy v0.9.31

> 参照 workbuddy2api 补齐四项治理能力：429/402 冷却、会话粘性、积分保底、成本折算。

## 背景

对同类中转项目做了一轮能力对比：

| 项目 | 星 | 定位 |
|---|---|---|
| `linguo2625469/workbuddy2api-panel` | 2009★ | Go，Web 面板 + 账号池 + 任务自动化 |
| `ardeyouxipianyi/workbuddy2api-hub` | 646★ | Python，双区域网关 + 成本折算 |

（搜索 provider 当时不可用，改用 `gh` 找到；两者同源，都基于已删库的
`Sliverkiss/workbuddy2api`。）

逐条在代码里 grep 验证过"缺失"属实后，补齐以下四项。

## 1. 上游错误冷却与熔断

新模块 `gateway/cooldown.py`，参考 panel 的错误分类治理：

```
429  → 软冷却 600s 起，连续触发按 2 倍指数退避，封顶 2h
402  → 硬冷却至次日 04:00（余额不足，签到回血才恢复）
404  → 固定 60s 短冷却
连续失败 → 熔断（阈值 3，退避 30m×2^n，封顶 6h）
```

### 为什么必须有

此前 429 是**直接透传**给客户端的 —— 排查中发现 **73 次 429 全部原样失败**，
而池里有 17 个账号：一个号被限流完全可以换一个，余额耗尽更该立刻停用。

没有冷却的后果：被限流的账号仍留在候选集里，**每个请求都可能再撞一次
同样的错误**，客户端看到的是随机失败，而不是「账号暂时不可用、已自动切换」。

### 一个关键判定

额度耗尽**也可能是 429**（历史实测 `code=14018 Credits exhausted`）。
所以按语义区分：命中额度关键词 → 硬冷却；其余 429 → 软冷却。
两类处理方式完全不同（一个等签到回血，一个退避一会儿就好）。

### 一个易错点

**模型不存在（`11102`）不惩罚账号** —— 那是换号就能解决的，不是账号的错。
若连它一起冷却，会把好账号白白罚掉。

## 2. 会话粘性

新模块 `gateway/session_sticky.py`：同一会话绑定同一账号，TTL 30m 滚动续期，
失败自动解绑。

客户端不传 `conversation_id` 时，用 `system + 首条 user` 哈希派生会话键
（`d-` 前缀）—— 这是 panel 的做法，**通用 OpenAI 客户端也能享受粘性**。

此前每请求独立选号，多轮对话会在账号之间跳，表现为「多轮对话突然忘了
前面说了什么」。

粘性是**软偏好**：绑定的账号若已冷却/停用/拉黑，自动落回普通选号，
绝不把坏账号硬塞给请求。

## 3. 积分保底

新模块 `gateway/credit_floor.py`，参考 panel 的 `pool.credit_floor`。

### 实测依据

`credit_usage_snapshots.json` 里 31 个账号中 **6 个余额 < 100，其中几个为 0**。
拿余额为 0 的账号跑请求，只会不断撞额度错误 —— 白白占用候选位、
拖慢选号，还让客户端看到随机失败。

### 与 panel 的差异（如实说明）

panel 能区分 tier 0（实测免费）/ tier 1（无观测）/ tier 2（实测收费）三档，
只对 tier 2 施加保底。本网关**没有**那个观测账本，因此：

- 默认 `AB_CREDIT_FLOOR=0`（**关闭**），行为与现在完全一致；
- 开启后对已知触底的账号生效；
- **永不返回空集合** —— 全部触底时回退原候选集，让上游返回真实错误。

## 4. 成本折算

新模块 `gateway/pricing.py`，参考 hub 的 OpenRouter 价估算：
把 token 折算成等价美元，缓存命中/未命中分档计价。

### 与 hub 的差异（如实说明）

hub 会定期**联网**拉 OpenRouter 全量价目表并按版本留档。
本网关**不联网取价** —— 中转网关不该为了一个显示数字引入外部依赖和失败面。

改为：

- 内置一份小价表（美元 / 每百万 token），覆盖本项目实际在用的模型；
- 未收录的模型返回 `None`，界面显示「—」而不是编一个数字；
- 可用 `AB_PRICING_JSON` 指向自定义价表覆盖补充。

## 修复：成本字段写进去了却读不出来

本次开发中发现并修掉的一个真实缺陷。

给明细加了 `cost` 字段，但 SQLite 表**没有对应的列** —— 写进去后读回来
丢失，已知模型的成本恒为 `None`。

更危险的是老库：生产库在 v0.9.29 就已建好 `usage_logs`，
而 `CREATE TABLE IF NOT EXISTS` 对**已存在的表不做任何事**，
直接部署会撞 `no such column: cost`。

已补三处：

1. 建表时加 `cost REAL`；
2. 新增 `_ensure_column()`，在 `init_db()` 里幂等补列；
3. 插入/读取两侧同步映射（`None` 表示「未定价」，不是 0）。

**已实测**：模拟 v0.9.29 老库（15 列）→ 迁移后 16 列且含 `cost`。

## 升级说明

重建容器即可，`/data` 数据不受影响。

新增可选环境变量（**都有默认值，无需配置**）：

| 变量 | 默认 | 含义 |
| :--- | :--- | :--- |
| `AB_STICKY_ENABLED` | `1` | 会话粘性开关 |
| `AB_STICKY_TTL` | `1800` | 会话绑定 TTL（秒） |
| `AB_CREDIT_FLOOR` | `0` | 积分保底阈值（0 = 关闭） |
| `AB_FREE_MODELS` | 空 | 免费模型名单（逗号分隔，仅保底开启时有用） |
| `AB_PRICING_JSON` | 空 | 自定义价表路径 |
| `AB_CD_SOFT_BASE` / `_MAX` | `600` / `7200` | 429 软冷却基数与封顶 |
| `AB_CD_HARD_HOUR` | `4` | 402 解封时刻（次日 04:00） |
| `AB_CD_BREAKER_*` | `3` / `1800` / `21600` | 熔断阈值 / 基数 / 封顶 |

数据库会自动补 `cost` 列（幂等），无需手工迁移。

**行为变化**：升级后，被限流或余额耗尽的账号会自动退出自动轮询一段时间，
而不是继续撞错误 —— 客户端看到的失败会明显减少。
