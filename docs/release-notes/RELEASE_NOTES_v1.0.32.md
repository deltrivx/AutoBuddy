官方用量同步判定改为**只看官方数据**，不再受网关账本逐模型明细有无的影响。

## 一、现象

积分统计页同时显示两件互相矛盾的事：

- 「已同步 **4/4** 个当前账号」
- 「**部分账号**官方用量未同步」
- 失败账号的官方数值一栏显示「—」

该警告在 v1.0.28 修过一次但**依然存在**。

## 二、上一版修错了方向

v1.0.28 把原来硬编码的状态字段改成「如实反映」，但判定式写成了：

```python
_acc_has_detail = bool(_new_daily) and bool(_acc_models)
```

这两个数据源的**语义本来就不同**：

| 变量 | 来源 | 语义 |
| :--- | :--- | :--- |
| `_new_daily` | 官方接口返回的 daily | **数据取到了吗** |
| `_acc_models` | 网关 `token_stats.db` 的 `usage_logs` 表 | **明细完整吗** |

`usage_logs` 只记录**经过网关调用过模型**的请求。所以：

> 一个只签到保活、从不走 API 的账号 —— `daily` 有数据，但 `usage_logs` 为空
> → 被那个 `and` 判成 `ok=false` → 进 `errors[]` → 官方前端报「部分账号未同步」
> 而「已同步 4/4」用的是 `daily`（4 个都有数据）→ **两个提示自相矛盾**

「失败账号显示 —」指的也不是「官方用量没取到」，而是**逐模型明细那一栏为空**
（那一栏本来就来自网关账本，只签到账号不会有记录）。

## 三、修法

拆成两个独立判据：

```python
_acc_has_data   = bool(_new_daily)    # ok 只看官方数据
_acc_has_detail = bool(_acc_models)   # 明细单独表达，不升级为失败

"ok":               _acc_has_data,
"detailTruncated":  not _acc_has_detail,
"error":            None if _acc_has_data else "该账号无官方用量数据（上游未返回）",
"errors":           [按 ok=False 聚合]
```

### 四种组合的行为

| 账号情况 | `ok` | `detailTruncated` | `error` | 进 `errors[]` |
| :--- | :--- | :--- | :--- | :--- |
| 有 daily、无账本明细（只签到） | **`true`** | `true` | `null` | **否** |
| 有 daily、有账本明细（正常） | `true` | `false` | `null` | 否 |
| 无 daily（真取不到官方数据） | **`false`** | `true` | 有文案 | **是** |

**警告功能保留**：真的取不到官方数据的账号，提示照常出现。不是把警告关掉。

## 四、为什么上次的测试没拦住

v1.0.28 那版 23 项断言**全是源码结构匹配**：

```python
check("ok 由 _acc_has_detail 决定", re.search(r'"ok":\s*_acc_has_detail', body))
```

它只验证「字段按预期写法赋值了」，**没有一项验证真实数据下的行为**。所以
`ok` 依赖 `_acc_models` 这个语义错误，照样能让 23 项全绿。

本次升级为**行为断言**（共 30 项）：

| 组 | 内容 |
| :--- | :--- |
| [A] 源码契约 | 保留原 23 项中的结构断言，防止字段被改回硬编码 |
| [A2] 判据独立性 | 断言 `_acc_has_data` 只依赖 `_new_daily`、`_acc_has_detail` 只依赖 `_acc_models` |
| [A3] 回归 | `errors[]` 只由 `ok=False` 聚合，不受 `detailTruncated` 影响 |
| **[B] 行为契约** | 用**可执行的判定函数副本**跑四种数据组合，断言 `ok` 的真实取值 |
| **[B2] 聚合行为** | 4 个只签到账号 → `errors[]` 必须为空（缺陷核心断言） |
| **[B3] 反证** | 断言「旧逻辑在同场景下判 False」—— 证明测试确实能抓住此缺陷 |

**有效性已验证**：同一份测试，用修复前的旧代码跑 **5 项 FAIL**，用修复后的
新代码跑 **30 项全过**。

## 五、影响

| 项 | 说明 |
| :--- | :--- |
| 改动量 | 3 处赋值（`ok` / `error` / 新增 `_acc_has_data`）+ 注释 |
| 业务逻辑 | 零改动。只改状态字段的取值来源 |
| 用户可见 | 只签到账号不再触发「部分账号未同步」；真失败的账号仍会提示 |
| 遗留验证项 | `detailTruncated=true` 是否会让官方前端另报「明细不完整」的提示 —— 需容器内实测确认，本地无法验证 |
