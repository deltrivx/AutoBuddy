> 本版起于一个现象：**每个账号前面又出现了三个桌面图标**。
> 排查后发现，真正的问题不是「图标回来了」，而是**整个补丁系统早就静默失效了**。

## 1. 根因：补丁全失效，而且失败被吞掉了

官方版本升级后，把压缩产物里的变量名整体重排了一遍。
而补丁脚本的**锚点全部把旧变量名写死**，于是**每一条都失配**。更糟的是：

- 锚点失配时脚本只打印一行提示就继续；
- 构建流程又把失败吞掉。

结果就是：**补丁一个字节都没改，镜像构建却照样 success。**

实证 —— 线上容器内的产物与官方原始文件**完全相同**，即上一版的补丁**一个字节都没改**。
所以三个桌面图标、产品槽位、导入本机账号、权限检测、桌面状态图标**全部复活**。

## 2. 重写补丁脚本：锚点自适应 + 失配即失败

- **锚点不再依赖压缩变量名**：一律用稳定的**文案 / 类名 / 元素 id** 定位，再回溯到调用起点，
  变量名从匹配结果里现取。
- **锚点失配 = 构建失败**：脚本收集所有失败项，末尾以**非零码退出**；
  构建流程去掉兜底吞错。
- **锁定上游版本**：改为锁定具体版本号，避免上游发版静默改变结构。

## 3. 移除清单扩充（新结构下重新逐条校准）

| 目标 | 结果 |
| :--- | :--- |
| 后端的硬编码本地地址 | → 改为跟随当前访问来源 |
| 账号卡片头部三个图标 | 整块移除 |
| 账号卡片底部三个产品槽位 | 整块移除 |
| 「当前账号」徽章组件 | 返回值清空 |
| 桌面程序运行状态图标组 | 整块移除 |
| 导入本机账号按钮 | 整块移除 |
| Token 统计页的数据来源分类 Tab | 整块移除 |
| 「Token 总览」冗余标题 | 整块移除 |
| CLI 专属的「查看请求明细」按钮 | 移除 |
| 设置页 5 个桌面向区块 | 组件返回值清空 |

新增移除的 5 个设置区块，对应「其他边缘功能不需要」：

- **权限检测**：检测 macOS 完全磁盘访问，容器里不存在该能力。
- **启动设置**：开机静默启动到托盘，纯桌面登录项 / 托盘概念。
- **自动更新**：容器里升级靠镜像重建，自更新只会写进易失层。
- **限额监听**：两个开关分别依赖「扫描桌面程序日志」与「向桌面客户端装 hook」，容器里两者都不存在。
- **CodeBuddy CLI 自动轮换**：随 CLI 一并移除。

**保留**「外观」（浅色/深色主题，WebUI 里真实可用）与「自动签到」（核心功能）。

## 4. 彻底移除 CodeBuddy CLI（不是隐藏）

- 镜像不再安装 CLI，并移除随之而来的运行依赖。
- 删除容器内 CLI 的绑定引导逻辑与启动步骤。
- 删除控制台里 CLI 相关的接口、样式与状态标记。
- Unraid 模板删除不再需要的挂载项，只保留两个端口与 `/data`。
- 镜像体积随之回落。

## 5. 文档

- README 删除「容器内使用 CodeBuddy CLI」整章及相关小节；
  账号调度链路收敛为**两层**；新增「容器化补丁机制（维护须知）」章节。
- 明确项目定位：**只做账号自动签到保活 + 提供 OpenAI 兼容 API**，除 `/data` 外不需要其他挂载。

## 升级方式

```bash
docker pull ghcr.io/deltrivx/workbuddy-switch:v0.3.11
docker pull ghcr.io/deltrivx/workbuddy-switch:latest
```

> Unraid 请通过容器模板重建，**不要手工拼接 `docker run`**。
> ⚠️ 本版**移除**了 `/workspace` 挂载项与 CLI 相关能力，请用**新版模板**重建容器，
> 不要沿用旧模板。数据目录不变（`/data`），升级不会动到账号数据。

## 不改变的行为

账号管理、自动签到、账号池调度与 Token 统计**全部保持不变**。
本版收敛的是功能范围（移除 CLI 与 5 个桌面专属设置区块）与补丁可靠性。
