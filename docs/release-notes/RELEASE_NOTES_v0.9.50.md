> 补齐 MoviePilot 同款核心交互：**自动生成企微应用底部菜单**（点按钮即交互），而非让用户手打命令。

## 背景

用户指出：参考 MoviePilot 实现内置交互，**不是手动配置那种**。此前 v0.9.47 只做了
「被动文字回复」（用户发 `help` 才回指令清单）—— 用户根本不知道能打什么，不算交互。

MoviePilot 的做法（`app/modules/wechat/wechat.py` 的 `create_menus`）是：配置保存后
**自动调企微 `menu/create` 注册应用底部菜单**，成员点按钮即触发，企微把按钮 key
作为 `EventKey` 回调过来。本版照做。

## 实现

### ① 菜单命令表与报文（`gateway/notify.py`）

- `WECOM_MENU_COMMANDS`：10 个按钮，分「常用 / 任务 / 通知」三组；
- `wecom_menu_spec()` 按分组构造企微报文，**自动受协议上限约束**：一级菜单 ≤ 3、
  每个一级下二级 ≤ 5（单命令组直接做一级按钮，避免出现空壳分组）；
- `MENU_KEY_TO_CMD`：按钮 key → 命令（点「网关状态」等价于手打 `status`）。

### ② 菜单管理

- `_wecom_token()`：抽出 token 获取（与发消息同源）；
- `create_wecom_menus()` / `delete_wecom_menus()`：注册/删除，**幂等**（覆盖式更新，不会堆积），
  失败只返回错误信息、不影响配置保存（菜单还依赖可信 IP 等条件）。

### ③ 自动建菜单 + 菜单点击路由

- `PUT /api/notify` 保存配置后：若企微三要素就绪，**自动注册菜单**，返回值带 `menu` 字段
  （成功/失败都如实回传，前端可提示）；
- 新增 `POST /api/notify/menu`（`{"action":"create"|"delete"}`）支持手动重建/删除；
- 回调端点支持 **`event` 消息**：菜单点击没有 `Content`，命令在 `EventKey` 里
  —— 补上映射，否则点按钮毫无反应。

### ④ 菜单按钮一览

| 分组 | 按钮 |
|---|---|
| 常用 | 网关状态 / 积分消耗 / 账号余额 / 模型数量 |
| 任务 | 任务进度 / 启动任务 / 全部签到 |
| 通知 | 开启通知 / 关闭通知 / 帮助 |

## 测试

新增 `_test_wecom_menu.py`（18 项）：命令表完整性、报文受 3/5 上限约束、
所有按钮有 key 且能映射成命令、菜单点击→命令路由、空配置健壮性（不抛异常）、
源码契约（menu/create + menu/delete + `/api/notify/menu`）。
全量 30 个测试文件全绿；Python 语法 + 内嵌 JS `node --check` 通过。

## 升级说明

重建容器后，在设置页「通知管理 → 企业微信」保存一次配置即会自动注册菜单
（也可调 `/api/notify/menu` 手动重建）。随后在企业微信里打开 AutoBuddy 应用，
底部即可看到菜单按钮，点击直接拿到结果。
