# AutoBuddy v0.7.0

> 统一账号来源（修好「按钮在、一点就报 account not found」）、每日任务改为自动关联账号、设置页自动签到迁至每日任务。

## 1. 功能失效的真正根因：账号来源不统一

### 现象
账号卡片上「启用/停用」「设为首选」「检测账号」「已调用 N 次」控件齐全，但一点就失败。

### 实测
```
POST /api/account-pool/toggle  {"accountId":"3db04d0e...(一杯美式)"}
→ {"detail":"account not found"}

POST /api/account-health/probe {"accountId":"3db04d0e...(一杯美式)"}
→ {"detail":"account not found"}
```

### 根因
容器里有两份账号文件，内容并不一致：

| 文件 | 账号数 | 说明 |
|---|---|---|
| `/data/.autobuddy/accounts.json` | 6 | 容器自己的副本 |
| `/data/.wb-switch/accounts.json` | **8** | 官方维护，新账号（「一杯美式」）先出现在这里 |

- **展示**走响应层合并后的 8 个 → 卡片、控件都正常
- **写操作**打到网关，而网关的 `_load_accounts()` 只认 6 个 → `account not found`

展示与操作用了两个不同的账号来源，才是「按钮在但功能全失效」的真因。

### 修复
在 `_load_accounts()` 这**一个入口**上合并两份账号文件（按 ID 去重、字段互补）。所有依赖它的接口——切换、检测、刷新令牌、删除、轮询选号——**一并修好**。

修在唯一入口，而不是在每个接口各自打补丁。

## 2. 每日任务：参与账号改为自动关联

- 同样合并两份账号文件，与账号池**同一出处**，避免「账号页看得到、每日任务里没有」。
- **彻底移除手动加入**：后端 `extra_accounts` 配置字段、请求模型、前端输入框与保存逻辑全部清掉。

> 账号池本身就是唯一权威来源。再开一个手填入口，只会让「哪些账号在跑」出现两个答案。

## 3. 设置页「自动签到」迁至每日任务页

签到本质是每日成长任务的一个子集（任务清单里就有「每日签到」项），配置散在两页会让「到底哪份在生效」变得不可知。

- 二进制补丁把 `settings-auto-checkin` 加入移除清单（与 `settings-updates` 等同一条路径，不硬写）
- 每日任务页接管其全部配置项：**启用自动签到**、**保活阈值（天）**、**惰性刷新（小时）**
- 与原有的调度间隔、执行模式、执行记录合流，卡片更名为「自动签到与调度」

## 设计原则

**同一份数据只能有一个出处。**

- 展示与操作必须读同一个来源，否则就会出现「看得到、点不动」
- 配置项要跟着它所属的功能走，不要因为「原来在设置页」就留在设置页
- 修根因（唯一入口）优于修症状（逐个接口打补丁）
