## v0.9.56：通知管理前端对齐 MoviePilot + 推送中断事故记录

### 中断原因（用户问的「之前被中断是什么原因」）

两个独立问题叠加：
1. **AI 服务限流**：「The AI service needs a short break」——上游模型服务的临时限流，
   会话被掐断（模型侧问题，非用户环境）。用户确认代理无问题（实测 curl 200/0.8s）。
2. **FnOS 本机 git GnuTLS 与代理不兼容**：curl/gh（OpenSSL 栈）全通，
   git push（GnuTLS 栈）持续传输挂死（-110/TLS not properly terminated/443 超时）。
   三路兜底（代理重试/HTTP1.1/直连）全败。

**修法（已验证闭环，以后照用）**：git bundle → scp 到 Unraid → Unraid 克隆仓库 →
fetch bundle → ff merge → `gh auth token` 经 stdin 传 token（不落盘不回显）→
`git push https://x-access-token:${TOK}@github.com/...`。tag 同法（tag bundle）。
本地最后 `git fetch origin` 同步引用。

### 通知管理前端对齐 MoviePilot（v0.9.56 本体）

核实 MP 前端源码（AccountSettingNotification.vue + NotificationChannelCard.vue +
NotificationChannelInfoDialog.vue）后的真实模型，此前「一张长表单平铺」不是 MP 做法：

- 渠道以**卡片网格**呈现（启用绿点徽标 + 就绪状态 + 场景摘要，点击弹配置）
- **配置弹窗**：每渠道独立启用开关 / 消息场景标签多选 / 注册表驱动字段 / 底部「测试+确认」
- NotificationConf.enabled → `_enabled`（send 跳过停用渠道；send_test 不受限）
- switchs → `_scenes`（SCENES：daily_done/account_low/health/system；空=全部）

CDP 实测：两张渠道卡（企业微信/Telegram 均「已就绪」）、弹窗含
启用开关+4 场景标签+7 字段+测试/确认按钮。
「回调 词元」是浏览器自动翻译假象——API 返回原文正确（回调 Token）。

### 企微菜单无回复的真根因（v0.9.55，用户问的第二个问题）

PKCS7 填充块误写 16（AES 分组），企微官方协议（WXBizMsgCrypt）是 **32 字节**。
本地往返（自加密自解密）自洽测不出；真实企微消息按 32 字节块填充，按 16 校验
必然 bad pkcs7 padding → 403。v0.9.55 已修并实测（官方格式构造密文 → 解密 →
路由 → 回复 200，回复内容含 v0.9.55/账号池 24/模型 40）。
