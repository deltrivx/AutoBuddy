## 一、模型标签可以点了

账号卡片下方的每个模型标签现在都能点击切换：

| 状态 | 外观 | 含义 |
| :--- | :--- | :--- |
| 默认 | 灰底常规字 | 可用，参与轮询 |
| 已用 | 蓝底加粗 | 该账号**真实调用过**这个模型（原有设计，完整保留） |
| **已禁用** | **灰底 + 删除线** | **点击后进入，该账号不再参与这个模型的调用** |

交互上的几个考虑：

- **点击即切换**，再点一下恢复原色（若该模型被调用过，恢复后回到蓝色高亮）。
- **禁用优先于已用**。两个状态互斥，禁用会压掉蓝色高亮 —— 否则刚点掉的那个看起来像没反应。
- **不做成按钮墙**。标签默认没有边框和下划线，只有鼠标悬停或键盘聚焦时才显形。
- **灰掉而不是红掉**。红色读起来像故障告警，但这是你自己的选择，不是出错。
- **`已禁用 N` 徽章**。卡片标题旁显示计数，卡片折叠时也能看出这里动过手。
- **支持键盘**：`Tab` 聚焦 + `Enter` / `Space` 切换。

## 二、禁用是真的生效，不只是变个颜色

标签变色只是界面状态，关键是**网关是否真的不再把请求分给那个账号**。这一版做到了：

1. **选账号时就避开**。网关在挑账号之前先看这次要用哪个模型，
   把禁用了该模型的账号直接排除 —— 而不是等请求发出去、上游报错再回头。
2. **只影响当前模型**。该账号的其他模型完全不受影响，照常参与调用。
3. **别名一并挡住**。模型的别名（例如 `hy4` 指向的 `hy3`）会一起被挡住 ——
   否则换个写法就能绕过禁用。
4. **安全回退**。万一某个模型在**所有**账号上都被禁用，网关**不会**返回「无可用账号」，
   而是照常发出去、让上游返回真实错误。凭空编一个错误会掩盖真正的原因，反而更难排查。
5. **不影响历史行为**。不指定模型时不启用过滤，与升级前完全一致。

## 三、配置怎么存的

- 禁用策略单独保存，与账号池配置**完全分离**，两者互不覆盖。
- **只记「被禁用」的项**，没列出的模型一律视为可用 —— 所以官方上新模型时天生就是可用状态，
  不需要你做任何迁移。
- 写入采用「先写临时文件再原子替换」，不会留下半截损坏的配置。
- 万一配置文件缺失、损坏或格式不对，一律回退为「全部可用」，**绝不会影响正常调用**。

## 四、管理接口

| 接口 | 说明 |
| :--- | :--- |
| `GET /account-models/config` | 读取禁用策略 |
| `PUT /account-models/config` | 切换禁用：单点切换，或整份覆盖某账号的禁用列表 |
| `PUT /api/account-models` | 控制台用：转发禁用切换（点标签时触发） |

同时，账号卡片的数据接口与池状态接口都补充了禁用状态字段，供界面渲染。

## 不改变的行为

账号管理、自动签到、账号池调度（并行轮询 / 手动首选 / 请求级指定账号）、
Token 统计与既有模型别名路由 —— **全部保持不变**。
本次只新增了模型级禁用的可点击交互与对应的路由过滤。
