> 修复助手配置页「点击 OpenAI 兼容接口直接卡死」——PUT 保存时同步跑 LLM 探测（实测 102.1 秒）。

## 用户反馈

> 「智能助手的配置页面，点击 OpenAI 兼容接口直接卡死，还没配置就已经切换了」

## 实测根因（两个缺陷叠加）

复现 `PUT /api/assistant`（切 provider 走的就是它）：

```
耗时: 102.1 秒
probe = {"ok": false, "error": "未收到回答（检查地址、密钥与模型名）"}
```

### 1. 卡死

`assistant_put()` 保存后**同步跑一次 LLM 探测**，实测 **102.1 秒**
（探测要跑两轮 LLM：45s 超时 ×2 + 工具调用）。前端 await 同一个请求，
页面看着就像卡死。

**总开关按钮也走这个 PUT** —— 等于点一下「启用智能助手」也要等 100 秒。

### 2. 未配置就切换

`_save_config()` 在探测**之前**执行 —— provider 已被切成 `openai`，
但密钥是空的，助手进入坏状态。探测失败只影响返回的 `probe` 字段，
救不回已经落盘的配置。

（排查期间我的探测就把线上切成过这个坏状态，已恢复为 `gateway`。）

## 修复

### 1. PUT 不再自动探测

保存只落盘，**绝不探测**。想验证连通性请用「测试连通性」按钮
（`POST /api/assistant/test`，用户主动发起、有明确等待预期）。

保留 `probe: true` 显式开关（向后兼容旧调用方）。

### 2. 新增轻量切换接口

`POST /api/assistant/provider` —— 只换 provider，零网络开销、即时返回。
前端 provider 标签改走这个接口。

### 3. 缺密钥时明确提示而非静默生效

切到需要密钥的 provider 但没填密钥时，接口返回 `warn`，前端 toast 提示：

```
已切换到「OpenAI 兼容接口」，但还没填 API Key —— 助手暂时无法回答，
请补上密钥后点「测试连通性」。
```

## 顺带修掉一个体验问题

此前点「OpenAI 兼容接口」会**立即落盘**，用户还没来得及填地址和密钥，
助手就已经不能用了。现在切换与填配置是两步：先切换（带提示），
再填地址/密钥，最后「保存」+「测试连通性」验证。

## 测试

新增 `_test_assistant_switch.py`（**35 项**）：

- **PUT 不再自动探测**：只在显式 `probe: true` 时探测、保存逻辑在探测之前
  （保存永不被探测阻塞）、返回 `warn` 字段；
- **轻量切换接口**：存在、只落盘不探测（函数体内无 `assistant_reply`）、
  校验未知 provider、返回 warn；
- **前端接线**：provider 标签走新接口、POST+JSON body、防连点禁用态、
  ok/warn 两种 toast、失败兜底、**不再走 PUT**；
- **测试连通性接口保持独立**：仍存在、仍走探测、`save` 参数仍可用；
- **配置层 secret 三态语义未被破坏**；
- **行为验证**（真实配置层）：切 openai 后 `api_key` 为空 → warn 判据成立；
  填密钥后读到、不触发 warn；切回 gateway 正常。

全量 **44 个测试文件全绿**；Python 语法 + 内嵌 JS `node --check` 通过。
