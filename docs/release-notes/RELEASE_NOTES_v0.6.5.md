# AutoBuddy v0.6.5

> 账号池控件改为「无论账号什么状态都完整渲染」——数据缺失不再表现为功能缺失。

## 问题

`injectAccountPool()` 的逻辑是「标题能反查到账号才继续」，查不到就 `if (!acc) return;` 整条跳过。

后果：任何不在后端返回列表里的账号（刚添加的、昵称对不上的、还没同步的），其卡片上**什么都没有**——用户看到的就是「功能没做」。

## 修复

查得到用真数据；**查不到就用安全默认值建一个占位条目**（`_placeholder: true`），四个控件照常渲染：

| 控件 | 占位状态下的表现 |
|---|---|
| 启用/停用 | 显示「尚未同步 · 点击重试」，点击重新拉取账号池数据 |
| 设为首选 | 渲染但置灰，悬停说明原因（没有有效 accountId，写进去会是空值） |
| 检测账号 | 渲染，点击先刷新数据 |
| 调用次数 | **始终渲染**（0 也要给），无数据时显示「调用次数 —」 |

## 设计原则（本版确立）

**控件必须与数据状态解耦。**

- 有数据 → 用真数据渲染
- 没数据 → 用占位值渲染，并把「为什么点不动」讲清楚
- 绝不因为缺数据就把按钮藏掉——藏掉等于告诉用户「这功能不存在」

调用次数尤其典型：「没调用过」本身就是有效信息。缺了这个标签，用户无法区分「从没调用」和「功能不存在」。
