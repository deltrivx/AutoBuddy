# AutoBuddy v0.9.17

> P0 热修：修复 v0.9.16 导致的前端整站白屏。

## 事故

v0.9.16 发布后，前端**整站白屏** —— 所有页面打不开。

## 根因

`TEXT_REPLACEMENTS` 会对 **JS 资源**做改写，且该改写有**等长**约束：
替换前后**字节数必须一致**。

v0.9.16 新增的 Token → 词元 替换里：

```
按本地聚合 Token 从高到低排列。    43 字节
按单次调用词元从高到低排列。        42 字节   ← 少 1 字节
```

`Token`（5 字节）换成 `词元`（6 字节）时没有补填充字符，于是触发：

```
ValueError: 等长替换被破坏: 按本地聚合 Token 从高到低排列。 (43) != 按单次调用词元从高到低排列。 (42)
```

## 影响链

```
等长校验失败
  → /assets/index-*.js 返回 HTTP 500
  → React 应用未挂载（#root 为空）
  → 页面全白，任何前端功能不可用
```

注意：容器健康检查 `/health` **仍然是 healthy** —— 后端活着、前端资源挂了，
所以健康检查发现不了这类问题。

## 修复

改为等长写法（43 == 43）：

```
按本地聚合 Token 从高到低排列。    43 字节
按单次调用词元 从高到低排列。      43 字节   ✅
```

（在「词元」后补一个空格补齐字节。）

## 为什么没能在发布前发现

本次事故中，下列检查**全部通过**：

| 检查 | 结果 |
| :--- | :--- |
| 四模块 AST | ✅ 通过 |
| 注入 JS `node --check` | ✅ 通过 |
| 13 项单元测试 | ✅ 全绿 |
| 版本一致性自检 | ✅ 通过 |

它们都检查不了「替换表字节是否等长」这一约束 ——
只有真打开页面才会暴露。

## 新增回归测试

`_test_text_replacements.py`：逐条校验替换表的**字节等长**，不等长即失败并
打印差多少字节、需补几个填充字符。

测试直接解析 `gateway/web_proxy.py` 源码，而不是 `import web_proxy` ——
后者依赖 fastapi 等运行时包，本地/CI 未必装了，会造成误判。
而要校验的只是「替换表本身的字节长度」，不需要把服务跑起来。
