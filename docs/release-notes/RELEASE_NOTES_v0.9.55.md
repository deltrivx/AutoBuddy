> 修复企微菜单点击无回复的真根因：PKCS7 填充块误写 16 字节，企微官方协议是 32 字节。

## 根因（2026-10-13 真实回调实测）

企微菜单点击**有到达**回调端点、**签名校验通过**，但解密报
`bad pkcs7 padding`，返回 403——这就是「菜单没任何回复」的直接原因。

根因：企微官方加解密协议（WXBizMsgCrypt）的 PKCS7 填充块是 **32 字节**
（`block_size=32`），本实现误写成 AES 分组本身的 16。

为什么之前没发现：本地往返测试（自己加密自己解）用同一个块大小，
**自洽所以通过**；真实企微消息按官方 32 字节块填充，按 16 校验必然报
`bad pkcs7 padding`。

## 修复

- `_AES_BLOCK` 16 → **32**（对齐官方 WXBizMsgCrypt 语义）；
- 加密侧（回给企微的密文）同样按 32 字节块填充，企微后台可正确解密。

## 验证

用官方格式（32 字节块 PKCS7）构造密文解密：

```
✅ 32字节块（企微官方格式）解密通过 | corpid: wwcorp123
✅ 回程加密 padding 块=32（企微侧可解）
```

更新回归测试 `_test_wecom_callback_crypto.py`（18 项全过），其中边界断言
从旧的 16 字节预期改为官方 32 字节语义（旧断言正是这次修复的对象）。

## 用户侧仍需做的一步

菜单点击要通，还需保证**配置页的「回调 EncodingAESKey」与企微管理后台
「接收消息服务器」里的 EncodingAESKey 是同一个值**（两边一致才能互解）。
若两边不一致，现象同样是 padding 失败。修复后若仍不通，先核对这一个值。
