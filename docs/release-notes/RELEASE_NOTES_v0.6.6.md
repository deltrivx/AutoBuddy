# AutoBuddy v0.6.6

> 移除占位条目——账号池控件不再「硬写填加」。

## 问题

v0.6.5 为了让控件「总是出现」，引入了 `_placeholder` 占位条目：后端查不到账号时，前端自己造一个假条目，配上「尚未同步 · 点击重试」这样的文案。

**这本身就是硬写填加。** 它编造了现实中并不存在的账号状态，只是把「按钮不渲染」换成了「按钮渲染了、但内容是假造的」——问题被遮住了，而不是被修好了。

## 修复

彻底删掉 `_placeholder` 全套分支（9 处），职责重新划清：

| 层 | 责任 |
|---|---|
| **后端** | 把数据**补全**：每个账号都有真实的 `id` / `nickname` / `email` / `enabled` / `disabled` / `disabledSource` |
| **前端** | **忠实渲染**：取得到就用，取不到就 `console.warn` 并跳过，不用假数据遮盖 |

调用次数恢复直接显示真实值（0 也显示「已调用 0 次」——「没调用过」本身就是有效信息）。

## 原则

**字段完整性是后端的责任，前端的责任是忠实渲染。**

用占位数据掩盖后端缺口，会让「数据缺了」这个真问题永远发不现——下次再出同类问题，排查时看到的是「按钮在、只是点不动」，而真因在后端数据层，两者之间隔了一层假象。

正确顺序：先把后端数据补齐（v0.6.4 合并两份账号文件就是干这个的），再让前端用一套逻辑忠实渲染。
