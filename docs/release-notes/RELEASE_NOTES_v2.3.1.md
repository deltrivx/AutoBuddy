# AutoBuddy v2.3.1 发布说明

## 修复：智能路由页面此前完全不可用

v2.3.0 把「智能路由」做出来了，但上线即不可用 —— 打开路由页时「路由规则加载失败、路由组一直卡加载中」。v2.3.1 把这条核心链路修通了。

### 根因

路由组 / 规则数据本是前端经 WebUI 代理（:18090）直连 `/routing/rules`，但 WebUI 代理的 catch-all 路由会把未知路径转发到**官方 Switch 后端**（:57890）；而路由端点实际注册在**网关**（:18091）。于是请求打到了一个根本不认识 `/routing/*` 的上游，必然失败。

### 修复

- 在 WebUI 代理 `web_proxy.py` 增加一套 `/api/routing/*` 反向代理端点（groups / rules / resolve 的 GET/POST/PUT/DELETE 与预览），统一转发到网关（:18091）并透传登录态，复用现有 `_forward_gateway` 与 `require_user` 鉴权门。
- 前端 `wbLoadRoutingData` 改为请求 `/api/routing/rules`（走 WebUI 代理 → 网关），不再直连 `/routing/*`。
- 顺带把 `injectWbRouting` 的导航项插入顺序改为「每日任务之后、系统设置之前」（原先被 `appendChild` 到导航末尾）。

### CDP 实测验收（FnOS 测试实例）

- 导航顺序：`每日任务 → 智能路由 → 系统设置` ✅
- 路由规则区：「暂无规则…」（不再「加载失败」）✅
- 路由组区：「暂无路由组…」（不再「加载中…」）✅
- 两次测量（间隔 1.5s）规则区 / 组区包围盒完全一致：**无抖动** ✅
- 经代理的 `/api/routing/rules` 真实返回数据（未登录 401、登录后正常）✅
- 从 Unraid 导入的「尘星途」账号已出现在账号池并可参与调度的回归验证 ✅

### 升级说明

- 仅新增代理端点与前端调用路径调整，无破坏性变更；v2.3.0 的路由表（`routing_groups` / `routing_rules`）与账号池数据全部兼容保留。
- 升级后直接可用，无需手动迁移。
