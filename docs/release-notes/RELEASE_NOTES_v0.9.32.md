# AutoBuddy v0.9.32

> 调用量与白名单下沉到每个 API 密钥，修正设置页的主次关系。

## 问题

用户 2026-10-07 反馈：

> 设置页面的 API 的调用量和白名单，应该对应每个单独的 API 而不是全部，
> 意思就是每个单独的 API 后面有调用量和白名单才对，主次关系混乱

## 根因：两处归属层级都错了

**① 白名单只有全局一份**

它是 `_STATE["whitelist"]` 里的一个全局列表，语义是「名单内的 IP 免密钥放行」。
但设置页把它摆在**密钥列表前面**，于是看起来像「整个网关的总开关」，喧宾夺主。

**② 调用量虽然每行都有，但头部另有全局汇总**

每个密钥行本来就有 `调用 N 次`，可列表头部还挂着一句
「累计调用 N 次」——让人分不清这个数到底是网关的还是某个密钥的。

## 改法：属性跟着对象走

| 项目 | 改前 | 改后 |
| :--- | :--- | :--- |
| 白名单 | 仅全局一份，位于密钥列表**前** | **每个密钥行内**各一份 + 全局兜底（移到列表**后**） |
| 调用量 | 每行有，但头部另有全局汇总 | 每行有，徽章明确归属该密钥 |

### 后端

- 每个密钥新增 `whitelist` 字段（新建即为 `[]` = 不限制来源）；
- 新增 `set_key_whitelist()`；抽出 `_normalize_whitelist()` 供
  **全局与单密钥共用同一套解析规则**（逗号/换行分隔、去重保序），
  避免同一个输入框在两处行为不同；
- 新增 `_validate_ip_list()`（main.py），全局与单密钥共用同一份校验，
  非法 IP/CIDR 照样 400 并列出前几个非法项；
- `authenticate()` 新增 `client_host` 参数 ——
  **密钥级白名单真的参与鉴权**：

  | 情况 | 结果 |
  | :--- | :--- |
  | 密钥配了白名单，来源在名单内 | 放行 |
  | 密钥配了白名单，来源不在名单内 | 拒绝（`mode="ip_denied"`） |
  | 密钥没配白名单 | 不限制来源（旧行为） |
  | 不传 `client_host` | 跳过该检查（兼容内部调用） |

### 前端

- 每个密钥行显示「白名单 N 条 / 不限来源」徽章，点击就地展开编辑
  （含「添加当前 IP」），保存**只影响这一个密钥**；
- 全局白名单区块移到密钥列表**之后**，标题改为
  「全局 IP 白名单（免密钥 · 兜底）」。

## 刻意保留的两类白名单

它们不是重复实现，语义与层级都不同：

- **单密钥白名单**：「这个密钥许不许这个 IP 用」—— 归属到具体密钥；
- **全局白名单**：「要不要密钥」—— 兜底，作用于所有密钥之上。

靠**位置**（单个在前、全局在后）与**文案**区分主次，避免再混淆。

## 升级说明

重建容器即可，`/data` 数据不受影响。

- 现有密钥会自动获得空的 `whitelist` 字段（不限制来源，**行为不变**）；
- 原有全局白名单配置原样保留，只是 UI 位置移到了密钥列表之后；
- 无环境变量变更。

**行为变化**：只有当给某个密钥配置了白名单后，该密钥才会限制来源 IP。
未配置时与过去完全一致。
