# AutoBuddy v0.9.15

> 修复刷新后需先点「设置」、侧边栏标题统一、每日任务页区块结构对齐官方。

## 1. 修复：刷新后必须点「设置」才能点「每日任务」

### 现象

刷新页面后，「每日任务」直接点不动，得**先点一次「设置」**再回来才可用。

### 根因

`injectWbDaily()` 会先找页面里的 `<nav>`，找不到就直接 `return` 放弃：

```js
var nav = aside.querySelector("nav");
if (!nav) return;          // ← 刷新后 SPA 还没挂载出 nav，这里就放弃了
```

刷新后 SPA 往往尚未渲染出导航区，于是注入被跳过。
要等用户点「设置」引起 DOM 变化，`MutationObserver` 再次触发 `run()` 才补上导航项 ——
这就是「必须先点设置」的来源。

### 修复

在 `DOMContentLoaded` 之后补跑若干次（0 / 300 / 800 / 1500ms），
确保导航项与 hash 路由在刷新后即到位。

## 2. 侧边栏标题统一

| 原名 | 现名 |
| :--- | :--- |
| Token 统计 | **词元统计** |
| 设置 | **系统设置** |

实现上按导航项**完整文本**精确匹配后改名，**不做全局字符串替换** ——
「设置」这类短词在页面中出现频繁，全局替换必然误伤其它文案。

收拢态（只剩图标）的悬浮气泡读的是 `data-wb-label` 属性，
因此改名时同步更新该属性，避免提示仍是旧名。

## 3. 每日任务页区块结构对齐官方

### 差异

官方积分统计页是**标题在框外**：

```
SECTION
  ├─ H2  二级标题（如「官方积分消耗」）13px / 500 / line-height 20px
  └─ CARD  圆角框，内部只放内容
```

每日任务页原为**标题在框内**的自造结构：

```
CARD
  └─ 行：三级标题 + 副标题 + 内容
```

### 修复

把每个卡片的标题外提为卡片外的二级标题 `H2`，结构统一为
`SECTION > [H2, CARD(内容)]`，与官方一致。

改造在 DOM 层统一处理，而非逐个重写 `innerHTML` 字符串 ——
本页卡片由一长串拼好的 HTML 构成，逐处手改易漏且难维护；
统一处理后**新增卡片也会自动纳入**。

副标题 / 描述保留在卡片内，与官方一致。
