## 1. 为什么上一轮漏了

v0.3.13 的普查是按「桌面 / CLI **关键词**」筛的。这个筛法有个盲区：
**把已移除的产品当成功能卖点、写进正常句子的文案**，不含任何关键词，直接漏网。

这轮改成：把界面上**所有**中文文案抽出来，再对账号页、账号卡片、设置页、导航**逐个组件全量过**。

## 2. 账号管理页副标题（源码里的陈旧文案，已修）

原副标题把 `CodeBuddy IDE` / `CodeBuddy CLI` 说成本页的管理对象 ——
而这两个桌面端产品早在 v0.3.11 就被物理移除，容器里根本不存在。

| | 文案 |
| :--- | :--- |
| 改前 | 统一管理 WorkBuddy、CodeBuddy IDE 与 CodeBuddy CLI 账号、积分和签到状态。 |
| 改后 | 统一管理 WorkBuddy 账号、积分与签到状态，并为 API 网关提供账号。 |

新文案只描述容器里真实存在的两件事：账号 / 积分 / 签到管理 + 为 API 网关供号。

## 3. 修正上一版的一处判定依据

上一版对某个弹窗的结论是「无任何调用点」，**不准确**：它确实被渲染，死因是**状态永远不为真**。

> 结论相同但依据要修正 —— 这类「有调用点但状态恒假」的弹窗，必须查到状态写入的实际值，
> 不能只看调用点数量。

## 4. 顺带把三处「疑似残留」查实为死代码（不动）

| 文案 | 判定依据 |
| :--- | :--- |
| 复制会话到目标账号 / 如何授权 / 在 Finder 中显示 / 立即检测 | 弹窗组件有调用点，但触发状态恒为假 |
| 切换 CodeBuddy CLI / 关闭 CLI 并切换 | 唯一入口是已被移除的产品槽位 |
| 将注入凭证并重启 CodeBuddy IDE / CodeBuddy IDE 已切换 | 仅作为属性传递，无调用者 |

## 5. 「模型限额」徽章：确认容器内不可达

卡片的「模型限额」徽章一度被怀疑还有可见残留。查实：轮询确实在跑，
但它扫描的是**宿主机桌面程序的日志**，容器里没有 → 数据恒为空 → 徽章不可能渲染。

## 升级方式

```bash
docker pull ghcr.io/deltrivx/workbuddy-switch:v0.3.14
docker pull ghcr.io/deltrivx/workbuddy-switch:latest
```

> Unraid 请通过容器模板重建，**不要手工拼接 `docker run`**。
> 数据目录不变（`/data`），升级不会动到账号数据。

## 不改变的行为

账号管理、自动签到、账号池调度与 Token 统计全部保持不变。
本版只改一处界面文案，并完成一轮界面文案普查。
