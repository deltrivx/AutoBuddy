# AutoBuddy v0.7.5

> 每日任务页签到与凭据合并为一行（不再重复列账号）、恢复「任务记录」任务维度面板（SQLite 持久化）、服务名全盘对齐 AutoBuddy。

## 1. 签到与凭据合并显示，一个账号只出现一次

- **问题**：同一页面上，签到区与「参与账号」卡片各列了一遍同样的账号 —— 第一处说「某账号已签到」，第二处又说「某账号凭据已就绪」，看的人得自己在脑子里把两处对上号。这是从设置页迁移时留下的重复渲染。
- **修法**：以账号为主体合并为一张卡片「账号签到与凭据」，一个账号一行：

  | 位置 | 内容 | 数据来源 |
  | --- | --- | --- |
  | 左侧 | 账号名（唯一来源：账号池） | `/api/wb-daily/accounts` |
  | 右侧状态一 | 今日签到（今日已签到 / 今日未签到 / 无签到接口） | `/api/checkin/status`（实时） |
  | 右侧状态二 | 凭据（凭据就绪 / 缺刷新令牌） | 账号池 `has_rt` |

- 独立的「参与账号」卡片已删除，页面不再出现两组账号。
- 账号标识做多键归一（`id` / `user` / `name` / `email` 交叉索引），签到状态与历史流水都能稳定落到账号池同一条记录上。
- 海外版（ai）账号没有签到接口，显示「无签到接口」而不是被当成签到失败；鼠标悬停可看到连签天数与最近签到时间。

## 2. 恢复「任务记录」面板（任务维度，SQLite 持久化）

- **问题**：页面上只有「执行记录」——那是一轮一条的汇总，回答的是「这轮跑了没有」；但「某个任务今天做了没、上次什么时候成功」根本看不出来。签到日志也被合并进账号卡片后，任务维度就彻底没有视图了。
- **修法**：新增任务台账表 `wb_daily_tasks`（**一行 = 一个账号的一个任务项**），执行时从脚本输出就地归集任务项与结果：

  - 任务项覆盖：每日签到、自动领奖、大转盘抽奖、盲盒开启、喵喵旅行、批量接受任务、Buddy 展示等；
  - 结果归一为 `success` / `already` / `failed` / `info` 四档，并留存连签天数与原始行文（截断 300 字）便于排障；
  - 随执行轮次自动累积，与执行记录同受 200 轮剪枝保护，不会无限增长。

- 新增两个只读接口，面板「任务记录」卡片直接展示聚合视图：

  | 接口 | 用途 |
  | --- | --- |
  | `GET /api/wb-daily/tasks?limit=&account=` | 任务台账明细，可按账号过滤 |
  | `GET /api/wb-daily/task-summary` | 按任务项聚合：最近一次结果 + 成功次数 + 最近账号 |

- 卡片每行显示：任务名 · 最近执行时间 · 最近账号 · 连签天数 · 成功 N/M · 结果徽章。与「执行记录」互补 —— 那边按轮次看，这边按任务项看。

## 3. 服务名全盘对齐 AutoBuddy

- 侧边栏品牌实时校准不再只认「WorkBuddy Switch」：官方产物里的裸「WorkBuddy」形态如今也能被校正，且严格限定在侧边栏品牌节点（`aside div.truncate`）内，不会误伤正文里的业务文案。
- 容器入口 `autobuddy` 与展示名保持一致；官方 npm 包名 / 可执行文件名（`workbuddy-switch`）作为**底层依赖标识符**保留 —— 标识符一改容器立刻起不来。判据是「**展示名改、标识符不改**」。
- Unraid 模板（`AutoBuddy`）、镜像仓库（`ghcr.io/deltrivx/autobuddy`）、数据目录（`/data/.autobuddy`）、巡检探测项均已对齐。

- 「任务记录」从本轮执行开始积累；此前的历史轮次没有任务维度数据，属预期。
