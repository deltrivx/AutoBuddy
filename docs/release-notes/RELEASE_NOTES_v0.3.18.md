## 需求

账号卡片上的「已调用 N 次」在容器重建后会归零，需要修复。

## 诊断结果：是容器重建导致的，而且只有它会归零

| 计数 | 数据源 | 存储 | 容器重建后 |
| :--- | :--- | :--- | :--- |
| 账号池条 `已调用 N 次` | `gateway/main.py` 的 `_SELECTION_LOG` | **进程内存** | **清零** |
| `gatewayCalls`（v0.3.16 起前端不再显示） | `/data/.wb-switch/token_stats_logs.json` | **磁盘** | 保留 |

铁证：

- 新容器启动于 `17:51:17`（UTC），`[pool]` 日志最早一条 `17:51:19` —— 之前历史全部消失；
- `token_stats_logs.json` 里 **285 条**记录最早可追溯到 `09-18 03:11`（**跨重建保留**）；
- `RestartCount=0`，说明是**重建**新容器，不是崩溃重启。

所以「模型调用次数应该也重置」并不成立 —— 两个计数器的存储介质不同。

## 修复内容

把 `_SELECTION_LOG` 落盘到 `/data/.wb-switch/selection_logs.json`：

- **加载**：模块导入时恢复；文件缺失 / 损坏 / 结构不对一律返回空列表，**绝不抛异常**；
  逐条校验 `accountId` 存在，并裁到环形上限 200。
- **写入**：**整份重写**（上限 200 条约 20 KB，比追加更不容易写出半截 JSON），
  用 `tmp + os.replace` 做原子替换，进程被 kill 也不会留下坏文件；
  异常一律吞掉 —— **统计落盘失败绝不影响正常的 API 请求**。
- **并发**：写盘放在 `_SELECTION_LOCK` **内**，保证「后发生的 append」一定写出更新的整份快照，
  不会出现两个线程的快照乱序覆盖。
- **清零**：`POST /account-pool/selections/reset` 现在**同时清内存与磁盘**，
  否则下次重启会把旧流水又读回来，看起来像「清零没生效」。

## ⚠️ 语义澄清（重要）

落盘只是让计数**跨重启连续**，**不是**变成历史累计值。它依然是**滑动窗口**：

| 计数 | 窗口 | 含义 |
| :--- | ---: | :--- |
| 账号池条 `已调用 N 次` | 最近 **200** 次选账号 | 该账号在最近 200 次里出现几次 |
| `gatewayCalls` | 最近 **3000** 次调用 | 该账号在最近 3000 次里出现几次 |

两者都会随新请求滑动而衰减，只是账号计数现在不会再被重启清空。
