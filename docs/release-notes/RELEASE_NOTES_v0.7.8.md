# AutoBuddy v0.7.8

> 彻底根除「幽灵账号」残留，保障所有账号卡片操作（首选/启用/停用）通用可靠。

## 1. 为什么会产生「幽灵账号」

在之前的实现中，用户点击「删除账号」时：
- 后端删除了 `accounts.json` 中的账号数据；
- 清理了 `model_policy.json` 中的模型策略；
- 清理了 `account_policy.json` 中的停用策略；
- **但遗漏了 `account_pool_config.json`**：该文件里的 `enabledAccountIds`（白名单）和 `manualAccountId`（首选账号）仍保留着被删账号的 ID！

这就产生了「幽灵账号」——账号本身已被删除，但白名单里一直记着它的 ID。

## 2. 为什么导致新账号操作「点了没反应」

当用户在界面上操作任何账号（尤其是新账号）的「设为首选」或「停用/启用」时：
1. 前端会把当前的 `enabledAccountIds` 完整发给后端 `PUT /api/account-pool`；
2. 后端校验时发现列表里包含幽灵 ID，判定为未知账号直接返回 `400 Bad Request`；
3. 前端网络层此前没有检查错误码，导致操作失败却静默无提示、也不刷新页面，给用户的直观感受就是「点了毫无反应」；
4. 而「检测账号」走的是独立的 `/api/account-health/probe`，不提交白名单，因此唯独它能正常工作。

## 3. 彻底根治方案

1. **删除时同步清理**：
   在 `delete_account_api` 中补齐对 `account_pool_config.json` 的联动：一旦账号被删除，立刻从白名单数组中剔除；若被删账号恰好是首选账号，自动将首选重置为 `None` 并将模式退回 `auto`。
2. **读取时自动自愈**：
   在 `_load_pool_config` 中增加自愈逻辑，每次读取时自动与当前实际存在的有效账号比对，剔除任何陈旧或幽灵 ID 并回写落盘。
3. **更新时智能容错**：
   在 `update_account_pool` 中遇到未知 ID 时不再抛出 400 中断，而是自动过滤并保存有效 ID，保证正常操作绝不被阻塞。
4. **前端网络层错误捕获**：
   重构前端 `savePool`，补齐 HTTP 状态码校验与错误 Toast 提示，拒绝任何静默吞错行为。
