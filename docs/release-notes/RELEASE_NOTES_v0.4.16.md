这个版本改的是措辞与判定依据：把「账号被拦截」讲对，并说清重新扫码有没有用。

## 一、修复：不再把账号被拦截说成「风控」

此前上游返回 403 / 错误码 11140 时，界面称之为「账号被风控」。这个说法会把人
引向两个都不成立的方向：

| 猜想 | 实测 |
| :--- | :--- |
| 平台在审内容 | 发一句 `hi`、发 `1+1=?`，同样被拦 |
| 请求太频繁被限流 | 平均 182 次/小时、峰值 27 次/分钟，且限流应返回 429 并随时间恢复 |
| 请求头特征被识别 | 加 User-Agent / Accept / X-Requested-With，五种组合一律被拦 |
| 整站被限制 | 同一站点另有账号正常返回 |

真正的判定发生在**模型校验之前** —— 发一个不存在的模型名，正常账号回
「模型不存在」，被拦的账号仍是 403，连模型名都没走到。这是**账号级拦截**。

界面文案因此统一改为「账号被上游拦截」，「风控」一词不再出现。

## 二、修复：说清「重新扫码无效」

上游的提示原文是「内容未通过安全审核」，容易被读成「换个内容或换个登录方式就行」。
实测做了一次对照：同一账号重新扫码登录，换上一张**全新凭据**后——

| | 重扫前 | 重扫后 |
| :--- | :--- | :--- |
| 凭据指纹 | `7e8e41cd…` | `c81bd9eb…`（已换新） |
| 凭据长度 | 1532 | 1468 |
| 过期时间 | 沿用旧值 | 新的 |
| **探测结果** | 被拦 | **仍被拦** |

凭据确实换新了，拦截依旧。说明拦的是**账号本身**，不是某一张凭据。

所以提示不再含糊地说「重新登录没用」—— 那句话容易被读成「换个登录方式也许可以」。
现在在设置页写明：重新扫码登录**不会**解除拦截，需要的处置是换一个账号。

## 三、修复：提示只留结论一句

被拦截的提示此前会拖出一段处置建议。提示条一闪而过，读不了长文；建议移到设置页的
说明区，那里才有版面讲清前因后果。

现在提示条只显示：

```
账号甲：账号被上游拦截，暂时用不了
```

## 四、新增：设置页的「账号被拦截时怎么办」

在可用性巡检的设置区新增一节说明，讲清三件事：

- 拦截发生在模型校验之前，与请求内容、频率、请求头都无关；
- 重新扫码登录不会解除，换一张凭据也一样；
- 巡检会自动停用被拦截的账号，账号恢复正常后自动放回。

与既有的「登录过期」说明区并列 —— 这两种状态的处理方向完全相反，
混在一起会让人白折腾一次重新登录。

## 不改变的行为

- 账号有效性的判定标准不变，拦截状态照旧自动停用、恢复正常后自动放回。
- 模型级禁用的来源标记与「一键恢复」的行为不变。
- 提示条的配色三档（正常 / 被拦截 / 登录过期）不变。
