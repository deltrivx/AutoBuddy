## 2️⃣ 「当前 CLI 账号」为什么只有一个？

**原因**：设置页显示的「当前 CLI 账号」来自官方底层接口，官方只维护**一个**绑定账号 ——
它本质是「CLI 助手绑定哪个账号」，是单账号概念，所以永远只有一张卡对应得上。

**处理**：

- 设置页该区块顶部注入范围说明，讲清它只影响 CLI 助手、不影响网关的 API 调用；
- 账号卡片给被绑定的那张打上标记，不再看起来「只有它有状态」。

---

## 3️⃣ 其他账号看不到模型调用提示（根因修复）

**根因**：模型明细接口只读官方缓存，而官方**只对当前账号返回模型明细**
（其余账号恒为空），于是多个账号里只有一两个有调用记录。

**修复**：网关每次调用都把**实际服务该请求的账号**记录下来，
以**网关自己归因**为主数据源、官方缓存为补充。
实测全部账号都能显示各自调用过的模型。

---

## 4️⃣ Token 统计页两个面板恒为空（根因修复）

**根因**：后端返回的三个字段**恒为空数组**，而前端正是读它们来渲染的。

**修复**：

- 「用量分布」改为**按账号**聚合（网关没有「项目」概念）；
- 「消耗最高的调用」改为**按单次调用**排列（每条网关请求就是一次独立调用）；
- 趋势图的模型筛选数据按模型 × 日期填充，筛选可用。

**文案同步**：`按项目→按账号`、`消耗最高的会话→消耗最高的调用` 等。

云端流水合并时**补上账号归属**（原本被丢弃，导致全部落进「未归属账号」并占据 100%）；
未归因的历史记录改标为「未归因（升级前记录）」。

## 6️⃣ 缓存与链路清晰度

- **强制禁用响应缓存**：前端资源文件名带 hash 不随改动变化，浏览器可能一直用旧副本，
  表现为「改了却没生效」。现在 HTML / JS 响应禁用缓存。
- **README 增加「账号调度链路」表**：明确账号池、网关健康巡检、官方 CLI 自动轮换
  各自的作用范围与间隔，说明三者互补而非冲突。

## 升级方式

```bash
docker pull ghcr.io/deltrivx/workbuddy-switch:v0.3.8
docker pull ghcr.io/deltrivx/workbuddy-switch:latest
```

> Unraid 请通过容器模板重建，**不要手工拼接 `docker run`**。
> 数据目录不变（`/data`），升级不会动到账号数据。

## 不改变的行为

账号管理、自动签到、账号池调度与模型路由**全部保持不变**。
本版修的是「数据已经有了但界面看不到」与「文案失真」两类问题。
