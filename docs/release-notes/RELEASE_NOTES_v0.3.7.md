## ❓ 要回答的问题

「账号池里 1 个国内账号 + 4 个国际账号，并发调用时是**真的并行分摊**，还是**只用了其中一个**？」

在本版之前，这个问题**无法从网关侧回答**：

- 网关只有一个全局的「最近一次用了谁」，说不了「N 个并发请求分摊到了几个账号」。
- 上游按账号查用量的接口，对全部账号**一律返回 404**，走不通按账号归因。

所以本版先补上观测能力，再用真并发实测。

---

## 🛠️ 本次改动

### 1. 选账号流水（网关侧归因）

每次选账号都记录一条流水（保留最近 200 条），并打一行日志，可直接 `docker logs` 核对。

### 2. 新增观测接口

| 接口 | 说明 |
| :--- | :--- |
| `GET /account-pool/selections` | 返回总次数、参与账号数、各账号命中次数与最近明细 |
| `POST /account-pool/selections/reset` | 清空流水，便于做干净的压测观测 |

状态接口同时补充了各账号命中次数字段。

### 3. 修掉一个并发隐患

选账号时「读序号 + 递增」**不是原子操作**，若两个并发请求读到同一个序号，
就会双双落到同一账号上 —— 表现正是「并发时其实只用了其中一个」。
现在把这一步串起来。

### 4. 界面

账号卡片控制条新增 `已调用 N 次` 计数徽章（有调用时高亮）与清零按钮。

---

## 📊 实测结论

**20 并发请求（同一模型）**：

- `HTTP 200 × 20` 全部成功；
- 20 个请求**均匀分摊到全部 5 个账号，各 4 次**；
- 并发墙钟 3.91s，对比单请求均值 3.33s，确为**并发**而非串行；
- 日志中的选账号序列为严格轮询的 4 轮完整覆盖。

---

## 📌 语义边界

**一条对话请求仍由单个账号完成**（不拆请求，避免上下文与计费混乱），
**多个同时到达的独立请求才会分摊到不同账号**。

## 📦 升级方式

```bash
docker pull ghcr.io/deltrivx/workbuddy-switch:v0.3.7
docker pull ghcr.io/deltrivx/workbuddy-switch:latest
```

> Unraid 请通过容器模板重建，**不要手工拼接 `docker run`**。
> 数据目录不变（`/data`），升级不会动到账号数据。

## 不改变的行为

账号管理、自动签到、Token 统计与模型路由全部保持不变。
本版只新增观测能力并修掉一处并发隐患。
