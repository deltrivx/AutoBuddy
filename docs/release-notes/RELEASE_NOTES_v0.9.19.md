# AutoBuddy v0.9.19

> 词元统计页剩余的 Token 字段，改走运行时替换，彻底清零。

## 问题

你反馈「词元统计页面遍历所有字段还有 token 字段未替换成词元」——属实。
实测页面上残留 **6 处**：

```
[0] 输入 Token
[1] 输出 Token
[2] 左轴：Token · 右轴：调用次数
[3] 近 30 天 合计 420M Token · 2,778 次调用
[4] 2026-08-29 使用 0 Token，0 次调用；…
[5] 最近一年按天显示 Token 活跃度。
```

v0.9.17 时我只补了 5 个**已知短语**，这些没覆盖到。而且其中 [3] [4]
是**动态拼出来的串**（数字参与拼接），根本无法预先枚举。

## 为什么不走静态替换表

`TEXT_REPLACEMENTS` 对 JS 资源做的是**等长字节替换**，而：

| 字符串 | 编码 | 字节数 |
| :--- | :--- | :--- |
| `Token` | ASCII | 5 |
| `词元` | UTF-8 | 6 |

**恒差 +1 字节，永远配不平。** v0.9.16 正是栽在这里 —— 少 1 字节 →
`/assets/*.js` 返回 500 → React 不挂载 → 整站白屏。

就算硬凑空格把长度配平，文案里也会留下莫名其妙的多余空白
（比如「输入词元 」尾巴上一个空格，只为凑字节）。

## 方案：运行时替换

新增 `wbCiyuanRename()`，渲染后遍历 **TEXT_NODE** 做替换。

### 为什么这样做是安全的

「裸 Token 全局替换会把接口打挂」的风险，**来自元素属性被改写** ——
比如 `href="/api/token-stats"` 里的 Token 被换掉，请求就 404 了。

而 `wbCiyuanRename()` **只改 TEXT_NODE，完全不碰元素属性**，
所以路由与标识符天然不受影响。

### 为什么覆盖得住动态串

它在页面渲染后运行，看到的是**已经拼好的最终文案**，
所以像「420M Token」「0 Token，0 次调用」这类运行时拼出来的内容也能改。

### 为什么不会死循环

替换后文本里已经没有 `Token`，下一轮 `run()` 遍历时**无节点命中**、
不再写 DOM，循环自然终止。

若 React 重新渲染出含 Token 的文本，会被再次替换 ——
这正是期望行为（对抗 hydration 覆盖）。

## 回归防护

给 `_test_text_replacements.py` 补了一条检查：**禁止往静态表里塞
「ASCII → 中文」的替换**。这类需求一律改走运行时替换。
