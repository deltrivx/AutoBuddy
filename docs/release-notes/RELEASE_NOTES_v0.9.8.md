# AutoBuddy v0.9.8

> 移动端卡片图标同步显示、修复积分文案被误判为旅行图标、浮窗信息修正与对齐。

## 1. 移动端账号卡片右上角图标与 PC 同步显示

### 问题

PC 端正常，移动端竖屏下账号卡片右上角的两个图标（旅行 / 签到）都不显示。

### 根因

**不在我们注入的代码里，而在官方前端自身。** 这两个图标的容器带如下类名：

```html
class="hidden shrink-0 items-center gap-1 min-[420px]:flex"
```

- `hidden` → 默认 `display: none`
- `min-[420px]:flex` → 仅视口宽度 **≥420px** 才切换为 `flex`

而手机竖屏宽度普遍是 **390 / 375 / 360**，全部低于 420 —— 于是被官方自己的
响应式规则隐藏了。

### 实测证据

用真实浏览器在两种视口下探测同一元素：

| 视口 | `display` | 图标 |
| :--- | :--- | :--- |
| 1280px（PC） | `flex` | 可见 ✅ |
| 390px（手机） | `none` | 不可见 ❌ |

### 修复

注入样式无条件覆盖该断点，使移动端与 PC 显示同步：

```css
[class*="min-[420px]:flex"] { display: flex !important; }
```

## 2. 积分文案不再被误判为「旅行中」

### 问题

- 积分统计页的积分数据上方多出一个旅行飞机图标；
- 浮窗第一行本该是积分，却显示成飞机图标。

### 根因

旅行状态判定里有一条规则：**以「剩余」开头即算 `traveling`**。
而「**剩余积分**」恰好以「剩余」开头 —— 被误判成旅行状态，
整段文字被替换成飞机 SVG。

| 文案 | 原判定 | 应为 |
| :--- | :--- | :--- |
| `剩余积分` | traveling ❌ | 非旅行状态 |
| `剩余 37 分钟到达` | traveling ✅ | traveling |

### 修复

- 含「积分」的文案**直接排除**；
- 旅行倒计时改为按形态匹配：`剩余 + 数字 + 时间单位`（正则），
  不再使用裸的「剩余」前缀。

## 3. 浮窗第一行改为「总积分」

原标签为「剩余积分」，且因上述问题被渲染成飞机图标。
现标签改为「**总积分**」，数值取各账号当前持有积分之和（`currentRemaining`）。

> 注：`currentCapacity`（额度上限）与 `currentRemaining`（当前持有）是两个不同口径，
> 第一行保留 `currentRemaining`，即「我总共还有多少积分」。

## 4. 浮窗第三行账号池改为「启用 / 总数」

### 问题

显示 `11/11`，但实际有 4 个账号并未参与调用。

### 根因

原逻辑用 `usable`（**凭据可用**的账号数）。当所有账号凭据都正常时它就是 11，
于是分子分母相同。

### 修复

改用 `inPool`（**真正参与调度**的账号数）。实测数据：

```
gateway-info accounts: {"total": 11, "usable": 11, "inPool": 7}
```

修正后显示为 **7/11**。

## 5. 右下角用户球悬浮不再弹出文字提示

悬浮时点击展开的浮窗已包含全部信息，原生的
`账号：xxx（点击查看）` 气泡属重复噪声。已移除该 `title` 属性 ——
**只显示浮窗，不再有额外文字提示**。

## 6. 浮窗统计行对齐修正

标签与数值原为 `align-items: center`。两者字号与字重不同时，
视觉基线会错位。现改为 `baseline` 对齐，标签严格靠左、数值严格靠右。

## 7. 认证凭据写入增加幂等

在 v0.9.7「环境变量权威」的基础上补一条优化：

| 情况 | 行为 |
| :--- | :--- |
| 环境变量在场且**值不同** | 覆盖写入 |
| 环境变量在场且**值相同** | **不写库**（幂等） |
| 环境变量不在场 | 不写库（用户自设密码保留） |

此前每次启动都会无条件 `UPDATE`，导致 `updated_at` 无谓变动。
已用隔离临时库验证：`updated_at` 在值相同时保持不变。
