## 一、设置页新增「API 接入」面板

| 项 | 内容 |
| :--- | :--- |
| **对外访问地址** | 自动推导为 `http(s)://<当前主机>:18091/v1`；走域名或隧道时可手动改，改动记在浏览器本地，可一键恢复默认 |
| **接口端点** | `POST /v1/chat/completions`、`GET /v1/models`，点一下复制完整地址 |

| **密钥管理** | 新建 / 复制明文 / 停用 / 启用 / 删除 / 清空；每行显示掩码、调用次数、最近使用时间 |
| **连通性自检** | 容器内回环实测三步，专门用来定位「UI 能打开但 API 调不通」 |
| **调用示例** | 自动带上当前启用密钥的 `curl` 片段；另有「复制接入信息」一键导出全部要点 |

## 二、API 密钥

### 怎么用

1. 打开 `http://<NAS-IP>:18090` → **设置** → 拉到最下面 **API 接入**；
2. 点 **新建密钥**，起个名字（比如 `Sub2API`），密钥会**自动复制到剪贴板**；
3. 把面板上的 **对外访问地址** 填进客户端的 `base_url`，密钥填进 `api_key`。

### 密钥格式与鉴权

- 格式：`sk-wb-` + 32 位十六进制
- 两种请求头都支持：
  - `Authorization: Bearer sk-wb-…`
  - `x-api-key: sk-wb-…`
- `Bearer` 大小写不敏感，密钥首尾空格会被容忍
- 缺失 / 错误 / 已停用的密钥统一返回 `401`，并给出可读中文原因

### 默认不校验

**没有配置密钥的用户，行为与升级前完全一致** —— `/v1/*` 直接可调。
只有你把「强制 API 密钥校验」打开，才会开始拦截。

> 纯内网可以一直不开；一旦端口暴露到公网或经过隧道转发，**务必打开**。

## 三、两道门锁防线（防止把自己关在门外）

| 场景 | 拦截 |
| :--- | :--- |
| 一个可用密钥都没有，却想开启校验 | ❌ 拒绝，提示先建密钥 |
| 开启校验后，想停用**最后一个**启用中的密钥 | ❌ 拒绝 |
| 开启校验后，想删除**最后一个**启用中的密钥 | ❌ 拒绝 |
| 开启校验后，想清空全部密钥 | ❌ 拒绝 |

这四条挡的都是同一类事故：一键点下去，自己和所有下游客户端一起失去访问权限，
之后只能进容器手改文件才能救回来。

清空全密钥时**不会**顺手帮你把校验关掉 —— 静默降低安全性比多一次点击更糟。

## 四、为什么容器内读模型清单不受密钥影响

WebUI 代理（18090）和网关（18091）跑在同一个容器里，代理需要读 `/v1/models`
来渲染账号卡片下方的「可用模型」清单。如果一并拦截，一开密钥校验就会把 UI 自己弄坏。

所以：**来自 `127.0.0.1` 的请求免校验**。容器外的请求经 docker NAT 进来，
源地址是网桥地址而不是 `127.0.0.1`，因此放行回环不会把外部请求放进来。

## 五、顺带修掉一个真实隐患

内部调用会被宿主机上的全局代理劫持：NAS 上为了下载或科学上网设全局代理很常见，
一旦被代理接管，容器内的回环调用会被转发到代理上并返回 `404` ——
表现为「UI 打不开 / 模型清单为空」，但网关本身是好的。

现在 WebUI 代理的**全部内部调用**统一忽略代理环境变量；
而**网关访问上游模型服务的客户端保持默认** —— 那里恰恰需要代理环境变量才能出网。
两条路径的要求刚好相反，不能一刀切。

## 不改变的行为

账号管理、自动签到、账号池调度（并行/首选）、Token 统计与既有模型别名路由**全部保持不变**。
本次只新增了 API 接入的可见性与可配置性。
密钥文件在 `/data/.wb-switch/api_keys.json`，升级不会动到账号数据。
