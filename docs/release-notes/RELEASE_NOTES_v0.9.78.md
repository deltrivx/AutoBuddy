> 修正助手 provider 切换语义：切换 = 选编辑目标（不落盘），只有「保存」才提交。

## 用户反馈

> 「切换逻辑有问题，切换又没保存，提示我干嘛，仔细思考应该怎么处理」

## 演进：同一个地方错了两次

| 版本 | 做法 | 问题 |
|---|---|---|
| v0.9.69 前 | 切 provider 走 PUT，PUT 保存后**同步跑 LLM 探测** | 实测 **102.1 秒**，页面像卡死 |
| v0.9.77 | 新增专用接口，切即落盘 + 提示缺密钥 | **切换又没保存**——用户以为只是选一下，实际已提交；空手切换也弹「没填 API Key」纯属噪音 |

两次都没想清楚一件事：**「切 provider」根本不是提交动作**。

## 最终模型：这是配置页，不是开关面板

「切 provider」= **选择要编辑哪一组字段**。这才是配置页的标准语义。

### 1. 切换只改本地选中态，零网络请求、不落盘

点「OpenAI 兼容接口」→ 表单切成 openai 的字段（地址/密钥/模型），
页面位置不变、不发任何请求。

### 2. 只有「保存」才提交

保存时按**当前选中的** provider 收集字段，一次 PUT 完成。

### 3. 草稿保持（v0.9.77 埋的坑）

v0.9.77 的字段状态在 `renderFields` 函数内，切走再切回会把用户刚填的
地址/密钥**全丢掉**。现在每个 provider 各自记草稿，切回来恢复。

### 4. 提示策略：不打扰

- **空手切换**：不弹任何提示；
- **已动过表单再切走**：提醒一句「有未保存的修改，记得点保存」；
- **保存时缺密钥**：这才提示（此时是真问题）。

### 5. 修掉一个隐性 bug

`collect()` 原先读闭包里的**初始** `cur`——切到 openai 后保存，
仍会按 gateway 的字段规则收集（`supports_api_key=false`），
**地址和密钥被静默丢弃**。现在按选中态取 provider 定义。

## 清理

删除死接口 `POST /api/assistant/provider`——切换不再需要服务端参与
（零请求）。PUT 保存与「测试连通性」保持原有分工。
