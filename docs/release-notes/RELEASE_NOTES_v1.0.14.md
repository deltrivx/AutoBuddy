本版把「被上游风控标记」从「本地停用」里彻底拆出来：账号卡片出现独立徽章，同时推送通知。
**只通知，不自动停用，不碰账号数据文件。**

事情的起点是此前 16 个账号集体停用那次。复盘发现根因不是账号真的全出问题，而是本地把
两件不同的事记在了同一个地方：`account_policy.json` 是扁平的 `{account_id: source}`，
`source` 只有 manual 和 auto 两种值。上游说「这个号被拦」写进去是 auto，人主动停用写进去是
manual —— 看上去分开了，但「上游判定」这个信息本身没有位置放，最后只能挤进 auto 那一栏，
和真正的自动停用混成一锅。账号池里一眼扫过去，分不清哪些是上游封的、哪些是自己关的。

本版给前者单独立账。

## 新增：账号卡片风控标记 + 推送通知

**改了什么**：`gateway/risk_flag.py`（新模块）+ `gateway/main.py` 记录与下发 +
`gateway/notify.py` 新场景 + `gateway/web_proxy.py` 徽章与浮层。

**触发条件**：上游返回错误码 **11140**。只在转发路径的非 200 响应里识别，
兼容 `{"code": …}` 与 `{"data": {"code": …}}` 两种上游形状，只认数字 code。

**标记存在哪**：自己的状态文件 `account_risk_flags.json`。**不写** `account_policy.json`，
**不写** `accounts.json`。删除账号时同步清理该账号的标记。

**推送**：新场景 `account_risk_flagged`，同账号 1 小时内不重复推。内容含账号昵称、
上游错误码、首次与最近触发时间、累计次数，以及一句「该账号未被自动停用，是否停用请到界面人工决定」。

**与 v1.0.13 的 `account_risk_alert` 不合并**：那个是**推测** —— 调用侧连续失败 3 次，
可能是限流，网关已自动施加冷却，结论不确定。这个是**确诊** —— 上游亲手判定账号被拦，
凭据仍然有效，不是登录过期、不是限流、也不是余额不足。两者语义和后续处置完全不同，
合成一个场景，用户就分不清「可能被限流」和「确实被风控了」。


## 界面长什么样

徽章是一枚**实心红底白字**的盾牌感叹号，插在账号卡片右上角两个原有图标的前方。
颜色和形状上与琥珀色的「已停用」徽章刻意拉开差距 —— 形状不同、填充不同（实心 vs 描边）、
配色不同，避免任何人把它误读成停用状态。

点徽章弹出浮层，四行信息 + 一个操作按钮：

| 行 | 内容 |
| :--- | :--- |
| 原因 | 上游返回 11140：账号存在异常行为，请求被拦截 |
| 最近触发 | 本地时间，精确到分钟 |
| 历史次数 | 累计命中次数 |
| 说明 | 「这只是上游的风控记录，不是本地停用 —— 账号仍在正常参与调用，系统不会自动停用它。是否停用由你决定。」 |

按钮是「解除这个标记」，**只人工可点**，后端同样没有任何自动清除逻辑 —— 上游没说这个账号
恢复正常了，我们就不该擅自说它好了。

移动端（≤640px）浮层限制最大宽度，不溢出屏幕。


## 红线自检

- **只通知，不自动停用**：`autoDisableAccounts` 维持关闭。本版没有任何触碰账号停用表的代码路径，
  没有调用 `set_disabled`，`account_policy` 模块压根没被 import。
- **不碰账号数据文件**：`accounts.json` 两份全程未被读写。取昵称走带 60s 缓存的只读路径。
- **不本地出包**：镜像仍由 GitHub Actions 构建推送 GHCR。
- **风控标记不进停用表**：这是本版的核心设计，标记只落在 `account_risk_flags.json`。
- **单测覆盖红线**：`_test_risk_flag.py` 用 `tokenize` 剥掉注释和字符串后做静态断言，
  确认不 import `account_policy` / `notify`、无停用调用、不写账号数据文件、只写自己的状态文件、
  无自动清除路径。断言剥过源码，防止注释里写「不停用」而代码里照停。
