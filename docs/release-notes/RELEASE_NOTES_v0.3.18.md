## 修复内容：账号调用次数随容器重建归零

**诊断结果**：两个计数器的存储介质不同，所以只有账号维度的那个会归零。

| 计数 | 存储位置 | 容器重建后 |
| :--- | :--- | :--- |
| 账号池条 `已调用 N 次` | **进程内存** | **清零** |
| 模型维度的调用次数（v0.3.16 起前端不再显示） | **磁盘** | 保留 |

现在把账号调用流水落盘持久化：

- **加载**：启动时恢复；文件缺失 / 损坏 / 结构不对一律返回空，**绝不抛异常**。
- **写入**：整份重写并做原子替换，进程被强制终止也不会留下坏文件；
  异常一律吞掉 —— **统计落盘失败绝不影响正常的 API 请求**。
- **清零**：「清零统计」现在**同时清内存与磁盘**，
  否则下次重启会把旧流水又读回来，看起来像「清零没生效」。

## ⚠️ 语义澄清（重要）

落盘只是让计数**跨重启连续**，**不是**变成历史累计值。它依然是**滑动窗口**：

| 计数 | 窗口 | 含义 |
| :--- | ---: | :--- |
| 账号池条 `已调用 N 次` | 最近 **200** 次选账号 | 该账号在最近 200 次里出现几次 |
| 模型维度调用次数 | 最近 **3000** 次调用 | 该账号在最近 3000 次里出现几次 |

两者都会随新请求滑动而衰减，只是账号计数现在不会再被重启清空。
