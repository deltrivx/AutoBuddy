## 方法

补丁已把要移除的界面代码整块换成空，所以有个很好用的推论：

> **凡是在打完补丁的产物里还能找到的中文界面文案，就一定不在已抹除区间内。**

把这类文案全量抽出来，再按桌面 / CLI 关键词筛一遍，剩下 7 处。
逐个追查「打开入口是否已被抹除」后，只有一处是真问题。

## 1. 账号列表空状态引用了已移除的按钮（唯一真问题，已修）

```
t === "ai" ? <>
  <p>暂无国际版账号。</p>
  <p>请确认本机已安装 {客户端}（客户端下载域名 {域名}）并登录，
     再点击上方「导入本机国际版账号」；也可以直接「OAuth 登录」添加国际版账号。</p>
</> : "暂无账号。点击上方按钮导入本机账号或扫码登录。"
```

它在账号列表为空时渲染，却让用户去点**已经被删掉的**「导入本机国际版账号」/「导入本机账号」按钮；
而且「请确认本机已安装…」本身就是桌面端话术。属于指向不存在入口的误导文案。

**新文案**（都指向容器里真实存在的入口）：

- 国际版 →「国际版账号请用上方「OAuth 扫码添加」或「导入备份」添加。」
- 国内版 →「暂无账号。请用上方「OAuth 扫码添加」添加。」

## 2. 另外 6 处确认是死代码，不动

逐个查「打开入口」是否已被抹除，结论如下：

| 文案 | 结论 |
| :--- | :--- |
| `关闭 CLI 并切换` / `切换 CodeBuddy CLI` | 唯一入口是已被抹除的产品槽位按钮 → 不可达 |
| `将注入凭证并重启 CodeBuddy IDE` | 同上 → 不可达 |
| `点击下方「打开完全磁盘访问」` | 没有任何调用点 → 不可达 |
| `在 Finder 中显示` | 只在桌面分支下才渲染，浏览器分支不会触发；且响应层已把它改写为「在文件管理器中显示」 |
| `客户端` | 非前端残留（后端字符串表 / 表格列头） |

> 顺带确认了一个此前没查过的点：产品里有一套「是否运行在桌面壳中」的运行时判断，
> 全量核对所有桌面专属的动态加载路径，只有一处没加判断，
> 但它的渲染条件只由桌面分支设置，容器里不会触发。
