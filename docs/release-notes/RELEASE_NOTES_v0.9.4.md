## 1. README 全面重写

### 问题

原 README 是**功能清单式罗列**：一张「核心能力」表格，每行一句话。
读完知道「有什么」，但不知道**怎么用、为什么这样设计、出问题怎么办**。
更关键的是，账号×模型能力矩阵、可用性巡检的四种状态区分、
每日任务的两种模式这些**真正体现设计取舍的地方，一个字都没写**。

### 现在的结构

```
这个项目解决什么问题    ← 用痛点表格说清「为什么需要它」
    ↓
功能详解（6 节）         ← 每节讲清设计意图，不只是罗列
    ↓
部署方式（3 种）         ← Unraid / Compose / CLI，可直接复制
    ↓
端口与持久化 + 环境变量  ← 含完整变量表
    ↓
接入与调用               ← Base URL、密钥、cURL 示例
    ↓
运维与排障               ← 健康检查、日志说明、常见问题表
    ↓
致谢
```

### 新增的关键说明

- **「这个项目解决什么问题」痛点表**——把「单账号额度不够」「模型只有部分账号有权」
  「官方没 API」「账号会被回收」这些真实痛点与对应做法并列，一眼看懂定位；
- **账号 × 模型能力矩阵**——负向学习（被拒即拉黑 + 换号重试）与正向学习
  （成功即记录，优先挑已知支持的账号，且只在确有支持者时才收窄候选集）
  两条路径都讲清楚，以及「手动禁用不会被巡检自动放开」这条行为承诺；
- **可用性巡检四种状态表**——`valid` 绿 / `invalid` 红 / `restricted` 琥珀 /
  `unknown` 琥珀，并说明**为什么受限账号不能用红色**：
  它的凭据其实是好的，标红会误导用户去重新登录，而重登对此毫无帮助；
- **每日任务两种模式**——`完整任务` 与 `仅查询`（只读、不产生任何状态变更）的区别，
  以及账号自动关联、凭据只读共用（无烧号风险）的设计；
- **后台日志两层降噪**——access log 过滤 + 业务日志去重，各自的保留规则；
- **环境变量完整表**——含「设置后在界面锁定为不可修改」这类行为说明；
- **常见问题排查表**——`model not found` 怎么办、账号反复失败怎么查、
  界面改了没生效怎么刷新。

## 2. 后台日志彻底降噪（access log 过滤）

### 问题：业务日志去了重，access log 却完全没管

v0.9.0 引入了 `lprint()`，对 `[pool]` / `[rotate]` / `[health]` 三处高频业务日志做了
**相邻去重**。但那只管自家输出 —— **uvicorn 的 access log 一行都没过滤**。

实测容器日志最近 500 行里有 **251 行是 `INFO: ... GET ...`**，占一半：

```
INFO:     127.0.0.1:50264 - "GET /health HTTP/1.1" 200 OK                    ← 探活，每 60s
INFO:     192.168.31.10:54565 - "GET /api/status HTTP/1.1" 200 OK            ← 面板轮询，每几秒
INFO:     192.168.31.10:62342 - "GET /assets/index-B68YgHsw.css HTTP/1.1" 200 OK
INFO:     127.0.0.1:45572 - "GET /gateway/info HTTP/1.1" 200 OK
INFO:     192.168.31.10:51188 - "GET /api/rotate/logs HTTP/1.1" 200 OK
...
INFO:     192.168.31.5:50814 - "POST /v1/chat/completions HTTP/1.1" 200 OK   ← 真实请求被淹没
```

WebUI 每几秒轮询一次状态类接口、探活每分钟一次、页面加载再补一堆静态资源 ——
**真正的业务请求反而要翻半天才找得到**。

### 修复

在 WebUI 面板（`web_proxy.py`，:18090）与 API 网关（`main.py`，:18091）
两个进程各挂一个 `logging.Filter` 到 `uvicorn.access`：

- **过滤条件**：路径命中噪声清单**且**响应为 2xx **且** `200 OK`；
- **噪声清单**：`/health`、`/api/status`、`/api/gateway-info`、`/gateway/info`、
  `/api/model-health`、`/model-health/config`、`/api-keys/status`、`/api/api-keys`、
  `/api/checkin/logs`、`/api/rotate/logs`、`/api/rotate/status`、`/api/rate-limits`、
  `/assets/`、`/icon.png`、`/favicon.ico`；
- **保守边界**：只静音「明确无信息量的成功轮询」。
  **4xx / 5xx 一律保留**，登录、鉴权、业务请求全部保留 —— 不把故障线索一起静音。
- **幂等安装**：重复调用不会叠加过滤器。

过滤器逻辑已用 8 个用例逐一验证（探活 / 轮询 / 静态资源 / 网关信息 → 静音；
真实请求 / 4xx / 5xx / 登录 → 保留）。

## 3. 头像上传按钮排版修正

### 问题

设置页「账号资料」里，头像区结构是：

```
[大预览头像 52px]  [右侧竖排: 头像选择器网格]      ← 官方 + 6 预设 = 7 枚圆钮
                   [上传自定义头像（整行按钮）]   ← 被压在这里，独占一行
```

上传按钮是普通矩形按钮，**被压在选择器网格下方单独占一行**，
与上面一排圆钮视觉上完全脱节，看着像「被挤扁在下面」。

### 修复

把上传按钮**改造成一枚与官方/预设等大的圆钮**（42px，虚线边框 + 加号，
悬浮变主题色），并作为头像网格的**最后一枚**参与排布：

```
[大预览头像 52px]  [◯官方 ◯预设1 ◯预设2 ◯预设3 ◯预设4 ◯预设5 ◯预设6 ⊕上传]
                    ↑ 一行排满 8 枚，上传钮在最末，与圆钮视觉等高
```

- `wbBuildAvatarPicker()` 新增可选 `extraBtn` 参数，传进来就作为网格内最后一枚按钮；
- 新增 `.wb-avatar-upload` 样式（圆形、虚线边框、悬浮高亮）；
- 网格保留 `flex-wrap` —— 窄屏（手机）放不下时自然换行，不会挤出容器；
- **设置页与「修改资料」弹窗两处统一**为同一形态。
