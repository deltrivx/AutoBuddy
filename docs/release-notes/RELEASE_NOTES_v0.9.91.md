> 修掉密钥统计「累计调用」的数字错误 —— Default 实际调用 45,673 次，页面却显示 92 次。

## 一、问题

你反馈：

> Default 的 API 调用 45644 次，下面却说累计调用 62 次，原来的没取消，新的还不对

设置页「API 接入」里，Default 密钥行的情况是：

| 位置 | 显示 |
| :--- | :--- |
| 行内徽标 | 调用 45,644 次 |
| 新增统计子行 | 累计调用 **62** 次 |

同一个密钥、同一个指标，两个数字差 700 多倍。

## 二、根因

v0.9.90 新增的按密钥统计走的是这条链路：

```
/v1/chat/completions
  → _gateway_auth() 解析出 keyId
  → record_token_usage(..., key_id=...)
  → usage_logs.key_id 落库
  → token-stats 的 byKey 聚合
```

问题在于 **`byKey.calls` 只统计「带了 keyId 归因」的记录**，而 keyId 记账是 v0.9.90 才加的 —— 在那之前产生的四万多次调用，记录里根本没有 keyId 字段，全部无法归因。

所以：

| 数据源 | 覆盖范围 | Default 的值 |
| :--- | :--- | :--- |
| `api_keys.callCount` | 从密钥诞生起，全部历史 | 45,673 |
| `byKey.calls` | 仅 v0.9.90 之后的调用 | 92 |

统计子行用了后者，徽标用了前者，于是自相矛盾。

## 三、修复

**累计调用始终用 `api_keys.callCount`** —— 这是权威计数，每次成功调用都记，含全部历史。

今日调用与词元消耗仍来自 `byKey`（只有一个来源，历史无 keyId 无法回溯），并在 tooltip 里说明统计起点，不再让人误以为是全量数据。

顺带修掉一个问题：同一个数字在行内徽标和统计子行各出现一次。现徽标改为只显示「最近使用时间」，累计调用只出现在统计子行。

## 五、关于任务积分

你提到「签到入账 2200，任务积分为 0」。核查结果：**任务积分已经正常了**。

今天（10-17）的实际情况：

```
今日签到积分：2,200
今日任务积分：300        ← 已入账
```

来源是任务轮执行中产生的 3 笔领奖：

```
07:34:02 | claim | +100积分 | 🎁领奖[Sequential_Tasks_5]
07:36:36 | claim | +100积分 | 🎁领奖[Sequential_Tasks_5]
07:39:10 | claim | +100积分 | 🎁领奖[Sequential_Tasks_5]
```

之前看到 0 是因为查询时刻任务轮还没跑到领奖那一步（任务积分只认上游日志里 `+N积分` 格式的行，而今天前 20 分钟输出全是「已 claimed / 跳过 / 次数已用尽」这类无积分行）。
