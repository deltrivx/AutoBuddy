## 一、新增：一致性自检

有一类情况过去只能靠猜：账号卡片上的「检测账号」说凭据有效，可用性巡检却把同一个账号
点名为「凭据失效，建议重新登录」。同一个账号，两处结论相反，既不知道信哪个，
也不知道该从哪里查起。

巡检面板新增「一致性自检」，一次把全部账号的**凭据结论**与**模型结论**并排列出，
每一行都带上判定依据与建议：

| 结论 | 含义 | 建议 |
| :--- | :--- | :--- |
| 凭据有效 | 上游以「模型不存在」应答，说明已认下凭据 | 无需处理 |
| 账号受限 | 凭据有效，但请求被上游拦截 | 重新登录无效，需确认账号状态 |
| 凭据已失效 | 上游以鉴权类错误拒绝 | 重新登录该账号 |
| 未得出结论 | 探测被拒、网络异常或限流 | 稍后重试 |

自检是只读的，不修改任何配置。判定标准随响应一并给出，随时可查。

## 二、新增：探测结论按语义分类

探测结果过去只看 HTTP 状态码，而同一个状态码可能是完全不同的原因 —— 403 至少对应
凭据过期、内容审查、无模型权限三种。现在改为先看上游错误码，归入统一的语义类别，
账号侧与模型侧共用同一张表。

这样同一份上游响应，在账号卡片、巡检报告、自检面板上得到的是同一个结论。

## 三、修复：内容审查被误判为凭据失效

账号的请求被上游内容安全策略拦截时，上游返回 403。这个状态码此前被一律当作
「凭据失效」，于是界面提示重新登录 —— 而重新登录对此没有任何帮助，
排查方向从一开始就是错的。

现在单独识别为「账号受限」，与凭据失效区分开，并明确说明重新登录无效。

## 四、修复：巡检因内容审查批量禁用模型

同一个误判还有更重的后果：被拦截账号名下所有模型都被判为不可用，
并被写入禁用策略。一轮巡检下来，几个账号的模型清单全部变灰，只能逐项手动恢复。

内容审查现在归入「不写入策略」的一类，与限流、探测形态错误同等处理。

## 五、修复：账号探测的请求形态与真实调用不一致

账号探测此前使用非流式请求，而上游对非流式请求明确拒绝，返回「暂不支持非流式」。
探测因此**从未真正到达判定点**，却因为这个错误码落在「模型不存在」的范围里，
仍然回报「凭据有效」。

改为与真实调用一致的请求形态后，探测才真正测到了凭据。

## 六、修复：模型级结果推翻账号级结论

一轮巡检里，账号可能被判定两次：先用专门的账号探测，再由名下模型的探测结果反推。
此前后者的权重更高 —— 只要名下模型全部返回 403，凭据就被重新判死，
覆盖掉账号探测已经得出的结论。同一个账号在同一轮里的最终状态，取决于模型侧的错误码。

现在凭据有效性只由账号探测裁定，模型侧结果不再反推凭据状态。

## 不改变的行为

- 手动禁用的模型仍然受保护，自动巡检不会将其启用。
- 账号级停用的语义不变：仅影响自动轮询，显式指定该账号仍可调用。
- 巡检默认仍为关闭状态，间隔与账号范围的配置方式照旧。
