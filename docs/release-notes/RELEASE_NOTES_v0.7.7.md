# AutoBuddy v0.7.7

> 移除 401 审计落盘恢复纯净镜像；新增 IP 白名单免密钥（仅在开启密钥校验时显示并生效）。

## 1. 移除 401 审计落盘

v0.7.6 加的 `auth_fail_audit.jsonl` 取证机制已完成使命（成功定位到错密钥来源），按计划移除，恢复无副作用的标准镜像。

鉴权路径回到原状：不再有额外的文件写入与请求头采集。

## 2. 新增：IP 白名单免密钥

**要解决的问题**：固定出口 IP 的调用方（内网网关、CI、家里的机器）每次都得带密钥，密钥一轮换就漏改，直接 401 —— 这正是本次排查踩到的真实痛点。

**行为规则（开关联动）：**

| 强制密钥校验 | 白名单 UI | 白名单是否生效 |
| --- | --- | --- |
| 已开启 | 显示 | ✅ 生效 |
| 已关闭 | **隐藏** | ❌ 不生效（整体放行，无需白名单） |

**功能细节：**

- 支持**精确 IP**（`192.168.31.5`）与 **CIDR 网段**（`192.168.31.0/24`），一行一个或逗号分隔；
- 自动归一 IPv4-mapped IPv6（`::ffff:192.168.31.5`）；
- 非法条目在保存时明确报错，并指出是哪一条（不静默丢弃）；
- 「添加当前 IP」一键填入，走新增的 `GET /api/client-ip`（优先取 `X-Forwarded-For` / `X-Real-IP` 最左值，兼容反代部署）；
- 配置持久化在 `api_keys.json`；关闭校验时仅隐藏 UI、**不丢配置**，重新开启即恢复。

**鉴权顺序（自宽到严）：**

```
1. 未开启密钥校验     → 直接放行
2. loopback（同容器） → 放行（WebUI 代理读 /v1/models 不能被打断）
3. IP 白名单          → 免密钥放行（仅开启校验时生效）
4. 否则               → 校验 Authorization / x-api-key
```

## 3. 设计边界

- 白名单**只免去密钥**，不绕过 loopback 判定之外的任何检查；
- 关闭密钥校验时白名单不产生任何效果 —— 因此前端在该状态下隐藏整块 UI，避免展示一个「看似生效其实无效」的输入框。

## 4. 新增接口

| 接口 | 用途 |
| --- | --- |
| `PUT /api-keys/whitelist` | 整份替换白名单（网关侧） |
| `PUT /api/api-keys/whitelist` | 同上的控制台代理 |
| `GET /api/client-ip` | 返回调用者自身来源 IP，供「添加当前 IP」使用 |

## 5. 单测

新增 `_test_ip_whitelist.py`（17 项），钉死三件事：

1. `_ip_in_whitelist` 匹配语义：精确 IP、CIDR、IPv4-mapped IPv6、非法条目跳过；
2. `set_whitelist` 归一化：逗号/换行拆分、去重、去空、清空；
3. 持久化：白名单跨重启存活。
