> 修复回调字段重复注册导致 GET 回读被当成密钥（前端无法回显、后端取到字典而非字符串）。

## 缺陷（2026-10-13 实测）

企微渠道注册表里 `cb_token` / `cb_aes_key` 被**注册了两次**：
一处 `secret=False`（明文），另一处 `secret=True`。注册表按 key 覆盖，
**后者生效**，于是这两个回调字段被当成密钥处理：

- `GET /api/notify` 回读变成 `{"has_value": true}` 字典，前端无法回显已配置的 Token/AESKey；
- 后端 `_send_wecom` / 回调处理取到的也不是字符串，配置实际不生效。

同时确认回调 URL 字段 `cb_url` 保留（供用户记录公网地址）。

## 修复

删除重复注册项，回调三字段统一为明文字段（Token/AESKey 本就不是"绝密"级别，
且必须能回显给用户核对），并修正占位提示为 FRP/公网可达地址示例。

## 测试

`_test_notify.py` 新增「注册表字段无重复 key」防回归断言（26 项全过）。
全量 29 个测试文件全绿。

## 升级说明

重建容器即可。修复后设置页能正常回显回调 Token / AESKey，企微后台保存配置时的
echo 校验也能正确解密。
