> 修正统计页回归测试——兼容「线上已被替换」状态。v0.9.79 部署后旧品牌名文案已不存在，「规则命中 N 处」断言恒为 0 而误报失败，那正是修复生效的证据。

## 背景

v0.9.79 修复了统计页加载失败（签到接口上游劣化到 5~9 秒拖垮整页）与旧品牌名
`workbuddy-switch` → AutoBuddy。部署后回归测试 `_test_stats_page_fix.py`
反而失败了：

```
FAIL 规则 1 命中线上 JS（0 处）  <- got 0
FAIL 规则 2 命中线上 JS（0 处）  <- got 0
```

## 根因（测试缺陷，非代码缺陷）

测试断言的是「替换规则能命中线上 JS 的旧文案」。但修复一旦生效，
旧文案在响应里**已经不存在**，命中数自然为 0 —— 这恰恰是修复生效的证据。

测试没有兼容「已修复」状态，把成功当成了失败。

## 修复

改为**双态判定**：

| 线上状态 | 断言 |
|---|---|
| 旧文案已消失（修复已生效） | 新文案就位 + GitHub 仓库名未被动 |
| 旧文案仍在（待生效） | 规则能命中、替换后旧文案消失 |

两个分支统一用 `out` 变量做 `node --check`（原先 `out` 只在 else 分支定义，
走 if 分支会 `NameError` —— 这是上一轮修改时引入的二次缺陷，本次一并修掉）。

用例数 29 → **30**。

## 测试

  ok   线上旧文案已消失（修复已生效）

纯测试修正，不影响运行时代码。v0.9.79 的功能修复已上线验证：
`checkin/status` 响应 **0.002 秒**（原 7.72 秒），品牌名文案全部替换正确。
