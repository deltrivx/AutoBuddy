## 一、数据总览 = 默认主页

**之前**：打开站点落在账号管理，要看数据总览得点一下，URL 变成 `/#/wb-overview`。而且**刷新会掉回账号管理**（hash 被冲掉）。

**现在**：打开 `/` 直接就是数据总览，URL 干干净净没有任何后缀，刷新也不会跑。

| 操作 | URL |
| :--- | :--- |
| 打开站点 / | `/` → 数据总览 |
| 点「账号管理」 | `/#/accounts` → 账号管理 |
| 点「数据总览」 | `/` → 数据总览 |
| 点「词元统计」 | `/token-stats` |
| 点「每日任务」 | `/#/wb-daily` |
| 点「系统设置」 | `/settings` |

## 二、账号管理为什么用 hash 后缀

你要求「账户管理加页面后缀」。之所以不能像其他页面那样占一个真实路径，是因为**官方 SPA 只认四条路由**：

```
/                （账号管理，现在被数据总览占用）
/token-stats
/credit-stats
/settings
```

实测 `pushState` 到 `/accounts` 会被官方 SPA 打回 `/`，直接访问 `/accounts` 也一样落到 `/`。而 `/` 现在是数据总览的地盘，账号管理要一个能访问、能刷新的独立地址，只能走 hash 后缀。

## 三、部署脚本（含部署前 abort）

新增 `scripts/deploy.sh`：

```bash
./scripts/deploy.sh            # abort 当前任务 + 重启
./scripts/deploy.sh --sync     # 额外同步 gateway/*.py 并清 __pycache__
```

**为什么需要 abort 步骤**：之前直接 `docker restart` 会把正在跑的每日任务**硬杀**。那一轮的逐账号明细停在最后一次增量落库上（v0.9.90 起每 20 秒一次），用户看到的就是「任务莫名失败」。

现在先软中止：

```
DELETE /api/wb-daily/abort/{job_id}
  → _execute 的 CancelledError 分支落库 + 标记 aborted
  → 巡检稍后自动从剩余账号续跑
```

比硬杀干净得多。脚本会等任务真正结束（最多 30 秒）再重启，没有任务在跑时直接跳过。

`--sync` 还会顺手清掉 `__pycache__` —— v0.9.89 踩过的坑：源码 md5 明明一致，但陈旧字节码让新代码完全不生效。

## 四、过程中修掉的两个真 bug

### 1. 账号管理拦截错对象

`nav.querySelector('a[href="/"]')` 命中的是**我新插入的数据总览链接**（它的 href 现在也是 `/`），于是：

- 数据总览链接的 id 被改成 `wb-nav-accounts`
- 拦截器绑到了概览链接上
- 结果：**六个选项卡一个都不高亮**

现显式排除两个注入的视图链接。

### 2. 点「每日任务」后后缀被清掉

清 hash 的通用处理器绑在「所有非概览链接」上，把每日任务刚设好的 `#/wb-daily` 当成残留后缀抹掉：

```
点「每日任务」→ URL 变成 /  → 高亮错成「数据总览」→ 刷新回不去
```

现只给官方链接挂这个清理逻辑。

另外加了视图状态指纹（`hash|path`），掐断 `pushState → popstate → SPA 重渲染 → MutationObserver → run()` 这条无限循环链。
