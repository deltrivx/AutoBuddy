> 这版没有新功能，是一次**自我更正 + 机制加固**：修正 v0.3.14 的错误结论，
> 并把由此暴露的「静默失效」隐患堵上。

## 1. 更正：那句副标题用户从来没见过

v0.3.14 把账号页副标题记作「用户可见的真问题」。**不成立。**

响应层里**早就有一条针对它的等长替换**，从 v0.3.8 起就在跑 ——
浏览器拿到的一直是**改写后**的文案。v0.3.14 只看了源头、没查响应层，
把一个「源码级陈旧」误判成了「用户可见缺陷」。

**性质修正**：不是用户可见 bug，而是**源码里残留着描述已移除产品的文案 + 一条掩盖它的运行时补丁**。

## 2. 清理：删掉那条已经永远命不中的响应层规则

v0.3.14 把该文案改到了源头，于是响应层那条规则的匹配串在资源里不再存在 ——
**一条永远命不中的死规则**。已删除。

**顺带确立的选型原则**：源头能改的结构性文案**优先在源头改**。
因为源头替换要求锚点**恰好命中 1 次**，失配会让构建直接失败；
而响应层替换命不中时**静默无操作** —— 正是「补丁全失效但构建 success」那类事故的同一形状。

## 3. 加固：响应层替换加「零命中告警」（并修掉它自己的误报）

响应层替换现在统计命中数，一条都没命中时打一行日志：

```
[webui] 文案替换未命中（上游文案可能已变，请复核）: <原串>
```

不抛异常（避免请求 500），但 `docker logs | grep 文案替换未命中` 就能发现上游改文案导致的静默失效。

**初版这里自己就踩了一个坑**：检查对 HTML 响应也执行，而这几条是**前端界面文案、只存在于 JS 资源里**，
HTML 外壳里根本没有它们 —— 于是**每个 HTML 请求都误报**。修正为只在 JS 响应上检查，
且每个串只告警一次，避免刷屏。

## 4. 顺带审计：端口清理规则命中 0 属预期

响应层里还有几条改写硬编码后端地址的兜底规则，实测命中 **0** ——
因为源头补丁把唯一的硬编码地址换掉之后就没事可做了。
它们保留作**兜底网**（上游若在别处新写硬编码地址仍能掰回），已在代码注释里写明「命中 0 属预期，不是失效」。

## 5. 验收

- 容器内热推送实测：HTML / JS 均 200，替换全部命中，`docker logs` 里告警 / 异常 **0** 条；
- 浏览器复验：账号页副标题 = `统一管理 WorkBuddy 账号、积分与签到状态，并为 API 网关提供账号。`

## 不改变的行为

账号管理、自动签到、账号池调度与 Token 统计全部保持不变。
