# AutoBuddy v0.9.2

> 积分统计页新增总积分趋势折线图、签到状态接口缓存、修复签到徽章滞后。

## 1. 总积分趋势折线图

官方积分统计页原本只有两张图：**消耗（柱状，按日堆叠）** 与 **按模型分类（横向条形）**。
v0.9.2 按同一套卡片样式（同样的圆角容器、13px 标题、同色系）补齐了**总积分趋势折线图**，
插在消耗趋势之前，形成「总览 → 总积分趋势 → 消耗趋势 → 模型分类」的阅读顺序。

**数据两条腿走路：**

- **倒推（B）**：官方 `daily[]` 提供每日消耗序列，`currentRemaining` 是当前剩余。
  从今天往回累加每日消耗，即可还原历史上每天的剩余积分 —— 一上线就有完整曲线，不必等积累。
- **实测快照（A）**：每次成功取到 `credits/stats` 时，把当天的（剩余、总额度）落一条。
  后续真实数据逐渐覆盖倒推值。

图上做了**视觉区分**：实心点为实测值，空心点为推算值，左上角标注「当前剩余」，
右上角说明图例含义。这样既立刻可用，又不会把估算值伪装成实测值。

## 2. 签到状态接口 60 秒缓存

**实测数据**：

| 接口 | 耗时 |
| --- | --- |
| `/api/checkin/status` | **2.34s**（上游 1.46s） |
| `/api/wb-daily/accounts` | 0.03s |
| `/api/checkin/logs` | 0.03s |
| `/api/travel/status` | 0.03s |

签到状态是全站最慢的只读接口 —— 它要逐个账号去 WorkBuddy 服务端实时查询；
而其它三个走本地 SQLite。但它的语义只是「今天签没签」，分钟级陈旧度完全可接受。

现在缓存 60 秒，命中直接返回，刷新页面不再等两秒多。**只缓存成功响应**，
失败不缓存 —— 否则一次上游抖动会被缓存放大成整分钟的「查不到签到状态」。

## 3. 修复签到徽章滞后于飞机图标

**症状**：刷新页面后账号的飞机旅行图标很快显示，但签到图标要很久才出来。

**根因**：前端用 `Promise.all([三个接口])`，必须三个都到齐才渲染。
签到状态是最慢的那个（2.34s），于是飞机图标（走 travel/status，0.03s）
秒出，签到徽章被拖住两秒多。

**修法**：改为**各自到齐就渲染** —— 账号列表与签到日志（0.03s）先画出，
签到状态到达后局部补写。状态未到时徽章显示「查询中…」，
而不是误报「暂无记录」。

## 4. Buddy 徽章细节

承接 v0.9.1，移除外围虚线框，仅保留图标本身的虚线绘制与配色，
使无 Buddy / 未旅行 / 旅行中三态外形视觉统一。
