> 每日任务新增**巡检自动恢复**与**签到/任务调度拆分**；数据总览改为 Tremor 式仪表盘，六个页面宽度与横向位置全部统一；另修今日消耗口径、断点续跑、保存按钮位置等一批问题。

## 一、任务巡检：被中断的任务自动恢复

### 1. 原来会错过一整天

任务被中断（容器重启、被 kill、执行超时）后，只能等下一轮调度才恢复。默认间隔 12 小时，用户配到 24 小时就更久 —— 中断当天的剩余账号要等到第二天才跑，当天收益直接丢掉。

典型场景：22 个账号跑了 4 个，容器重启，剩下 18 个当天不会再跑。

### 2. 现在：默认 1 小时巡检一次

新增一个独立于 `interval_hours` 的更短周期，到点就检查最近一轮是否中断，是则立即从剩余账号续跑：

| 项 | 值 |
| :--- | :--- |
| 默认周期 | 60 分钟 |
| 可配范围 | 5 – 1440 分钟 |
| 配置位置 | 每日任务页 → 任务巡检卡片 |

**约束**：巡检间隔必须小于执行间隔，否则等巡检到点时下一轮调度也到期了，巡检等于没做。保存时若违反会明确提示：

```
已保存，但巡检间隔 60 分钟 ≥ 执行间隔 12 小时，巡检不会生效
```

界面也会显示「待恢复的中断任务」与「下次巡检」时间，当前有没有欠账一眼可见。

### 3. 恢复哪种轮次

巡检靠 DB 新增的 `kind` 列直接判断中断的那一轮是签到轮还是任务轮，不依赖任务台账是否已落库。老库会自动迁移（`ALTER TABLE ... ADD COLUMN kind`，缺省 `task`）。

## 二、签到 / 任务调度拆分

### 1. 原来混在一起的后果

「自动签到与调度」是一张卡，签到与任务共用一个开关、一个间隔、一个 `last_run_at`：

- 跑完签到会把任务轮的下次执行时间也推后 12 小时
- 想只停任务、保留签到？做不到
- 想签到 6 小时一轮、任务 24 小时一轮？也做不到

### 2. 现在三张独立卡片

| 卡片 | 配置项 |
| :--- | :--- |
| 签到调度 | 启用开关、签到间隔、签到上次执行、签到下次到期 |
| 任务调度 | 启用开关、任务间隔、任务上次执行、任务下次到期 |
| 任务巡检 | 启用开关、巡检间隔、待恢复的中断任务、下次巡检 |

底层用两套独立的 `enabled` + `interval_hours` 与各自的 `last_run_at`，执行时按轮次类型给上游脚本传不同任务过滤：

```bash
# 签到轮
workbuddy_daily.py --no-desktop --tasks checkin

# 任务轮
workbuddy_daily.py --no-desktop --skip-tasks checkin
```

任一边单独停用不影响另一边。

> 任务轮用**黑名单**（跳过 checkin）而不是白名单枚举全部任务 —— 上游新增任务时不用回来改这里。

## 三、断点续跑

中断后的下一轮自动跳过已跑完的账号，从剩余账号继续。

上游脚本按账号串行执行，中断点之前的账号当天任务已经真做完、明细也已落库（积分 / 连签 / 等级 / 任务台账），所以「结算这 4 个收益」不需要额外动作，数据已经在库里。

账号匹配用「手机号前 2 位 + 后 2 位」组合 —— 实测脱敏号形如 `1  13*******60` 只露这四位，且该组合在 22 个账号内唯一（只用后 2 位会有 `03`/`41` 两组重复）。

## 四、数据总览仪表盘

概览页改为 Tremor 式布局：

- **8 张 KPI 卡**（两行四列）：账号池总积分、今日消耗、今日获得积分、累计任务积分、可用模型、今日调用、API 密钥、近 7 日消耗
- **近 30 天积分消耗趋势图**
- **每日任务卡**：执行中显示「执行中 2/24」，含进度条与当前账号
- **账号池分布**：启用/停用比例 + 正在调用列表
- **最近执行**：行可点，下方展开明细

数据全部走既有接口，零新增后端依赖；配色只用官方 CSS 变量，深浅主题自动切换。

### 正在调用列表

按调用顺序排列：最新被调用的账号排第一，别的账号被调用就升到第一、原第一退到第二。一行一个（左账号名、右调用次数），可见区域固定高度、超出部分纵向滚动，卡片大小不随账号数变化。

## 五、六个页面宽度与横向位置统一

以账号管理 / 词元统计 / 积分统计（1180px）为标准，系统设置、数据总览、每日任务全部拉齐。

实测三档视口下六个页面的左边缘与宽度集合各只剩一个值：

| 视口 | 左边缘 | 宽度 |
| :--- | :--- | :--- |
| PC 1440 | 115px | 1180px |
| PC 1920 | 355px | 1180px |
| MB 390 | 0px | 390px |

过程中修掉三个自踩的坑：

1. **对齐函数破坏对齐**：hash 视图下官方 wrap 是 `display:none`（0×0），仍去算差值，把 margin-left 压成 0
2. **宽度永远对不齐**：CSS 的 `max-width: 1180px !important` 盖过 JS 内联样式，grid 恒为 1180px
3. **合法差异被误杀**：差值阈值 400px 会把设置页真实的 412px 宽度差挡掉，导致设置页永远对不齐

## 六、数据口径修复

### 1. 「昨日消耗」改为「今日消耗」

改用 `summary.usageToday`（已由 `_reconcile_official_usage` 校准的准确值），不再用本地时间减一天去匹配 `daily` 的日期键 —— 跨时区/跨零点时会取错一天。

实测同一份响应里两个口径不一致：

```
summary.usageToday                       = 2347.97  ← 准确
sum(accounts[].daily[date=today].usage)  = 2669.06  ← 偏高
```

### 2. 账号池总积分徽标改为净值

原先徽标用 `usageToday`（纯消耗），永远显示成消耗值，与旁边「今日消耗」卡一模一样。现改为「今日获得 − 今日消耗」，正数绿箭头、负数红箭头、持平中性。

### 3. 日报「今日调用」口径

日报在 00:05 发送，此刻「今天」才过去 5 分钟，按今天统计必然接近 0。改按**昨日**统计，与积分部分同一口径。

## 七、其他修复

### 1. 移动端顶栏排版

根因是 **CSS 优先级**：桌面规则 `#wb-topbar-inner > .wb-tb-grid` 是 ID 选择器 (1,1,0)，媒体查询里的裸类 `.wb-tb-grid` 是 (0,1,0)，所以移动端的列数、padding、height 全部失效 —— grid 高 56px 溢出 48px 内盒、logo 落在 24px 而非 16px、主题图标与收纳按钮被摊开散在中间（实测 x=179 / x=279）。

三条规则改用同款 ID 选择器后全部生效，两按钮聚到右上角（306 / 346）。

### 2. 保存按钮找不到

操作按钮行原先被塞进「执行模式与账号保活」卡片内部，视觉上归到了保活那一卡，用户改完调度/巡检配置后找不到保存入口。现独立成一张卡，紧跟三张调度卡之后。

同时修掉一处悬空引用：拆分卡片上线后 `wbDailySaveConfig()` 仍引用已移除的 `wb-dl-enabled` / `wb-dl-interval`，一点保存就抛 TypeError。

### 3. 执行记录人话状态与点击明细

中断记录显示「进程中断，未完成」「执行超时，未完成」「已手动中止，未完成」，不再显示「退出码 0」「账号 0」这种看不懂的原始字段。

行可点，在**该行正下方**插入明细卡（跑了多少账号 / 任务完成数 / 失败原因 / 积分收益 / 逐账号表），再点一次收起。手风琴模式，同时只展开一个。

空明细不再显示「本轮没有账号级明细（可能是旧记录或任务未跑完）」—— 这类信息对用户没有任何意义。改为按该轮汇总信息给出「跑了多少 / 为什么停 / 收益多少」，中断轮也有内容可看。

### 4. 通知内容去重

同一场景连续两次推送内容完全相同时自动跳过，只有内容真的变了才放行。典型场景：模型巡检每 3 小时跑一轮，结果全是「无变化」，旧实现会把同一句原样推一遍又一遍。

按 `scene + 正文` 的 sha1 指纹比对；只对**成功推送过**的场景生效 —— 上一次失败不算数，否则一次网络抖动之后即使内容没变也永远不再推送了。

### 5. 导航高亮

原直接给 `<a>` 加官方的 `bg-foreground/[0.06]`，那是 React 自己管理的状态类，SPA 重渲染时会重新分配，出现「离开某页后仍高亮」「多个项同时高亮」。改用专用类 `wb-nav-active`，React 不认识它，高亮状态完全由我们控制。

## 八、已知取舍

- `/api/wb-daily/jobs` 是**进程内存态**，容器重启即丢。所以重启后若任务其实还在跑，页面会短暂显示静态态，等下一轮 wb-daily 上报后恢复。
- 词元统计的 `total = input + output` 把命中缓存的输入也全额计入。这与官方前端 `cacheRead / input` 的算法一致，是口径选择而非计算错误，本版未改。
