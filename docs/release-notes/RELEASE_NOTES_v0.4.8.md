## 一、修复：巡检进行中做的手动禁用会被悄悄抹掉

一轮巡检要真实探测几百个模型组合，耗时以分钟计。此前这一轮的开头和结尾是这样做的：

- **开场**读一次禁用策略，作为整轮的底稿；
- **结尾**把这份底稿连同本轮的探测结论一起写回。

问题出在这几分钟的间隔上。期间在账号卡片上点掉的模型（手动禁用），写进去的是**最新的**策略文件，
可巡检结尾又用**开场那份快照**把它整份盖了回去 —— 于是手动禁用凭空消失：卡片上显示着已禁用，
配置里却没有；点一下刷新或者进程重启，它更会「自己恢复」。

| | 修复前 | 修复后 |
| :--- | :--- | :--- |
| 巡检期间你在卡片上的改动 | 被开场快照覆盖 | 原样保留 |
| 本轮的探测判定 | 生效 | 生效，且只走自动通道 |

修复方式是把结尾的「整份写回」改成「**重新读一遍最新策略，只叠加本轮的探测结论**」：
本轮判定为不可用的照常自动禁用，判定为恢复的照常自动放开，而人工点下的一律不动。

## 二、手动禁用与自动禁用各走各的通道

巡检只处理**自己写入**的禁用项（界面上标为「巡检」），从不改动**手动禁用**的项（标为「已禁用」）。
两者从探测范围到落盘都是分开的：手动禁用的组合不进入探测清单，落盘时也不会被巡检的结论碰到。
因此巡检轮次进行多久、跑多少轮，都不会影响你手动关掉的那些模型。

## 不改变的行为

模型可用性巡检的开关与判定规则（限流跳过、凭据失效整账号跳过、整轮无有效信号作废）、
手动禁用的写入与来源保护、账号池调度（并行轮询 / 手动首选 / 请求级指定账号）、模型别名路由 ——
**全部保持不变**。

对外提供的 OpenAI 兼容接口、请求与响应字段**没有任何增删**。
